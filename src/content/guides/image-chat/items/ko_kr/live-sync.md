### 실시간 업데이트

Image Chat은 WebSocket 연결을 사용하여 모든 대화를 연결된 모든 사용자에게 실시간으로 동기화합니다. 누군가 새 마커를 만들거나, 댓글을 추가하거나, 토론을 삭제하면 같은 이미지를 보고 있는 다른 모든 사용자가 새로고침 없이 즉시 업데이트를 확인할 수 있습니다.

### WebSocket 동기화 작동 방식

Image Chat을 초기화하면 위젯이 FastComments 서버와 WebSocket 연결을 설정합니다. 이 연결은 사용자 세션 동안 열려 있으며 현재 이미지와 관련된 업데이트를 수신합니다.

WebSocket 시스템은 Image Chat을 위해 세 가지 유형의 브로드캐스트 메시지를 사용합니다. `new-image-chat` 이벤트는 누군가 이미지에 새 마커를 만들 때 발생합니다. `image-chat-updated` 이벤트는 누군가 기존 대화를 업데이트할 때 발생합니다. `deleted-image-chat` 이벤트는 누군가 마커를 삭제할 때 발생합니다.

### 브로드캐스트 ID 시스템

사용자가 자신의 작업이 다시 자신에게 브로드캐스트되는 에코 현상을 방지하기 위해, 각 업데이트에는 고유한 `broadcastId`가 포함됩니다. 사용자가 마커를 만들거나 업데이트하면 클라이언트는 해당 작업에 대한 UUID를 생성합니다. WebSocket이 업데이트를 모든 클라이언트에 브로드캐스트할 때, 원래 클라이언트는 자신의 `broadcastId`와 일치하기 때문에 해당 업데이트를 무시합니다.

이를 통해 사용자는 서버를 왕복할 때까지 기다리지 않고 UI에서 자신의 변경 사항을 즉시 확인할 수 있으며, 동시에 다른 모든 사용자도 업데이트를 받을 수 있습니다.

### 연결 복원력

네트워크 문제나 서버 유지보수로 인해 WebSocket 연결이 끊어지면 위젯이 자동으로 재연결을 시도합니다. 재연결 기간 동안 사용자는 기존 마커와 상호작용할 수 있지만, 연결이 다시 설정될 때까지 다른 사용자의 실시간 업데이트는 볼 수 없습니다.

재연결되면 위젯이 재동기화하여 누락된 업데이트가 없도록 합니다. 이 과정은 사용자 개입 없이 투명하게 이루어집니다.

### 대역폭 고려 사항

WebSocket 메시지는 가볍고 상태 동기화에 필요한 필수 정보만 포함합니다. 새 마커를 만드는 데는 일반적으로 1KB 미만의 대역폭이 사용됩니다. 또한 시스템에는 활동이 많은 기간 동안 메시지 빈도를 줄이기 위한 지능형 배칭이 포함되어 있습니다.

FastComments 대시보드의 사용량 지표는 `pubSubMessageCount`와 `pubSubBandwidth`를 추적하므로 사이트 전반의 실시간 동기화 활동을 모니터링할 수 있습니다.

### 탭 간 동기화

사용자가 여러 브라우저 탭에서 같은 페이지를 열어 놓은 경우, 한 탭의 업데이트가 다른 탭에 즉시 나타납니다. 이는 동일한 WebSocket 동기화 메커니즘을 통해 작동하며 추가 설정이 필요하지 않습니다.

사용자는 여러 기기에서 동시에 사이트를 열어 놓을 수 있으며, 모든 기기가 동기화 상태를 유지합니다. 데스크톱 컴퓨터에서 만든 마커는 두 기기가 같은 이미지를 보고 있는 경우 사용자의 태블릿에 즉시 나타납니다.

### 보안

WebSocket 메시지는 보안 연결(WSS)을 통해 전송되며, 테넌트 검증을 포함하여 사용자가 승인된 대화의 업데이트만 수신하도록 보장합니다. 서버는 무단 접근이나 조작을 방지하기 위해 모든 작업을 브로드캐스트하기 전에 검증합니다.

### 오프라인 동작

사용자가 완전히 오프라인 상태일 때는 기존 마커를 볼 수 있지만 새 마커를 만들거나 다른 사용자의 업데이트를 볼 수는 없습니다. 위젯은 오프라인 상태를 감지하여 적절한 메시지를 표시합니다.

사용자가 오프라인 상태에서 마커를 만들려다가 이후 온라인으로 돌아온 경우, 대기열에 추가되지 않고 작업이 실패하여 데이터 일관성이 보장됩니다. 사용자는 연결이 복구되면 작업을 다시 시도해야 합니다.

### 성능 영향

WebSocket 연결은 성능에 미미한 영향을 미칩니다. 연결은 업데이트가 없을 때 유휴 상태를 유지하며 활동이 발생할 때만 메시지를 처리합니다. 보통 수준의 마커 활동이 있는 일반적인 이미지에서 WebSocket은 이미지 자체를 렌더링하는 것보다 적은 CPU를 사용합니다.

수백 명의 동시 사용자와 높은 마커 생성 활동이 있는 페이지의 경우, 시스템이 수평적으로 확장되어 개별 클라이언트 연결에 영향을 주지 않고 성능을 유지합니다.

### 협업 사용 사례

실시간 동기화 덕분에 Image Chat은 협업 워크플로우에서 특히 강력합니다. 디자인 팀은 모든 사람이 마커 배치를 실시간으로 확인하면서 함께 목업을 검토할 수 있습니다. 고객 지원팀은 스크린샷에 협업하여 주석을 달아 문제를 파악할 수 있습니다. 교육 그룹은 모든 참여자가 서로의 마커가 생성되는 것을 실시간으로 확인하며 다이어그램을 토론할 수 있습니다.

즉각적인 피드백은 사용자가 업데이트를 보기 위해 새로고침해야 하는 기존 댓글 시스템에 비해 더 몰입감 있고 생산적인 협업 경험을 만들어냅니다.
