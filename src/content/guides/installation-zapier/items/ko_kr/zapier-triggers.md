## 트리거

FastComments에서 무언가 발생하면 트리거가 Zap을 시작합니다. 세 가지 모두 즉시 작동합니다: FastComments는 이벤트가 발생하는 순간 웹훅을 통해 Zapier에 전달합니다. 계정을 폴링하는 것이 없으며, 대기하는 동안 API 크레딧이 소모되지 않습니다.

| 트리거 | 발생 시 |
|---------|-----------|
| New Comment | 댓글이 게시됩니다. 기본적으로 승인된 비스팸 댓글만 트리거됩니다. |
| Updated Comment | 댓글이 편집, 승인, 투표, 고정, 잠금 또는 기타 방식으로 변경됩니다. |
| Deleted Comment | 댓글이 삭제됩니다. |

각 트리거는 전체 댓글을 반환합니다: id, 페이지 URL 및 URL ID, 댓글 작성자 이름 및 이메일, 마크다운 및 HTML 형식의 댓글 텍스트, 투표 수, 승인 및 스팸 플래그, 로케일, 도메인, 그리고 멘션. 이러한 필드는 Webhooks, Data Structures 섹션에 문서화된 웹훅 페이로드와 일치합니다.

## 옵션

**Domain.** 모든 트리거에는 선택적 도메인 필터가 있으며, 계정에 설정된 도메인 목록을 표시합니다. 비워두면 모든 도메인의 이벤트를 수신합니다.

**Include Unapproved and Spam Comments.** New Comment 트리거에만 적용됩니다. 검토 대기 중이거나 스팸으로 표시된 댓글은 기본적으로 건너뛰어집니다. 해당 댓글이 나중에 승인되면 Updated Comment 트리거가 해당 댓글에 대해 작동하므로, 표시되는 모든 댓글에 반응하도록 Zap을 설정하려면 승인된 필드에 필터를 적용한 Updated Comment를 사용합니다.

## 전달 방식

Zap을 켜면 계정에 웹훅 구독이 생성되며, Webhooks 페이지에서 소스 **API**와 함께 표시됩니다. Zap을 끄면 구독이 제거됩니다. Zapier 자체 제한에 따라 분당 수락 가능한 이벤트 수가 정해져 있습니다; FastComments는 실패한 전달을 점점 늘어나는 지연 시간으로 재시도하고, 6일 동안 계속 실패하는 구독은 비활성화합니다. 비활성화된 구독은 Webhooks 페이지에서 다시 활성화할 수 있으며, 또는 Zap을 끄고 다시 켜서 새 구독을 만들 수도 있습니다.

계정당 최대 50개의 API 구독을 보유할 수 있습니다. FastComments 트리거를 사용하는 각 Zap은 하나의 구독을 사용합니다.
