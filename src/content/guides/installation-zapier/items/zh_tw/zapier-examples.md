## 範例 Zaps

只需幾分鐘即可設定的工作流程。

**取得新評論的通知。** 新評論，接著使用 Slack「傳送頻道訊息」或 Discord「傳送頻道訊息」。將評論者名稱、評論內容與頁面 URL 映射到訊息中。加入網域過濾條件，以便每個站點通知不同的頻道。

**保留每則評論的日誌。** 新評論，接著使用 Google Sheets「建立試算表列」。將已刪除評論作為第二個 Zap，將評論 ID 追加為一列，讓試算表同時充當稽核追蹤。

**當評論獲准時寄送電子郵件給作者。** 使用「已更新評論」搭配 Zapier 篩選條件「Approved 為 true」，然後使用 Gmail「傳送電子郵件」。由於「已更新評論」會在每次變更時觸發，篩選條件使此 Zap 只對批准的情況作出回應。

**將評論者加入您的 CRM 或郵件列表。** 新評論，接著使用 HubSpot「建立或更新聯絡人」或 Mailchimp「新增或更新訂閱者」，使用評論者的電子郵件。加入任何人至行銷名單前，請遵守您的隱私政策與當地法規。

**從表單建立評論。** Typeform 或 Google Forms「新回應」，接著使用 FastComments「建立評論」，並提供您網站用於見證的頁面 URL ID。將 Approved 保持未勾選，以便在評論顯示前先審核。

**將公告發佈到資訊源。** Zapier 的 RSS「資訊源中新項目」，接著使用「建立資訊源貼文」，提供項目的標題、內容與連結。

**將會員配置為 SSO 使用者。** 使用 Memberstack、Memberful 或您自己的 webhook，接著「尋找 SSO 使用者」再以「尋找或建立」模式「建立 SSO 使用者」。

**升級被舉報的評論。** 「已更新評論」經過旗標計數大於零的篩選，接著使用 Trello「建立卡片」或 Linear「建立議題」，並附上評論 ID 與審核頁面的連結。

**在頁面上線時即發佈。** WordPress 或 Ghost「新文章」，接著「建立頁面」並使用文章 URL，讓頁面在第一則評論出現前即被列出並受限。

**歸檔已刪除的評論。** 「已刪除評論」，接著使用 Airtable「建立記錄」，將完整評論內容存入以符合保存規範。
