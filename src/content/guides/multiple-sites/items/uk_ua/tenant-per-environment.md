Досить поширеною практикою є створення окремого суб-орендаря (sub tenant) для кожного тестового або dev-середовища в FastComments. Кожен орендар має власну конфігурацію, дані та API-ключі. Конфігурацією, даними та користувачами не можна ділитися між орендарями.
Все ізольовано. Однак суперадміністратори батьківського орендаря можуть імперсонувати користувачів у дочірніх орендарях.

Є два підходи:

- Основний орендар — для production, а суб-орендарі — для тестових середовищ.
- Основний орендар використовується лише для білінгу, а кожен суб-орендарь — для prod, test тощо.

Перший підхід зазвичай простіший для розуміння користувачами, але це може залежати від вашої організації.

Орендарів можна створювати [тут](https://eu.fastcomments.com/auth/my-account/tenants), якщо у вас є відповідний пакет. Це також місце, де суперадміністратори
можуть імперсонувати користувачів. Орендарів також можна створювати через API для більш кастомізованих/автоматизованих налаштувань.

Незалежно від обраного підходу, вам доведеться додати модераторів і користувачів, які хочуть бачити production-дані, у орендаря "prod". Наприклад, якщо ви хочете
вибрати варіант B і використовувати батьківського орендаря для білінгу, а суб-орендаря — для "prod", вам потрібно буде додати орендаря, переключитися на нового орендаря та додати
своїх адміністраторів і модераторів для суб-орендаря.

І наостанок, для уточнення: сторінка Moderate Comments буде порожньою у батьківського орендаря при варіанті B.
