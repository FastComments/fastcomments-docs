FastComments को कस्टमाइज़ करने के लिए डिज़ाइन किया गया है। सुरक्षा कारणों से कमेंटिंग विजेट स्वयं एक iframe के अंदर चलता है, इसलिए कस्टम स्टाइलिंग लागू करने के लिए आपको दो तरीकों में से एक का पालन करना होगा।

पहला, सबसे आसान तरीका, और हमारे द्वारा पसंदीदा, [widget customization page](https://fastcomments.com/auth/my-account/customize-widget) का उपयोग करना है।

विजेट कस्टमाइज़ेशन पेज में, "Show Advanced Options" सेक्शन देखें, जिसके नीचे "Custom CSS" नाम से एक क्षेत्र है:

[app-screenshot-start url='/auth/my-account/customize-widget/new'; clickSelector = '.show-advanced-option'; selector = '.custom-css'; alt='विजेट कस्टमाइज़ेशन पेज पर Show Advanced Options के अंतर्गत Custom CSS एडिटर'; title='Custom CSS इनपुट क्षेत्र' app-screenshot-end]

इस तरीके के कुछ फायदे हैं:
1. दर्ज की गई CSS को यूज़र को भेजने से पहले minify किया जाता है, और एडिटिंग UI में फॉर्मेटिंग सुसंगत रखी जाती है।
2. आपको विजेट कस्टमाइज़ेशन UI के सभी फायदे मिलते हैं, उदाहरण के लिए अलग-अलग साइटों के लिए कमेंटिंग विजेट को आसानी से अलग-अलग कस्टमाइज़ करना।
3. जब हम कमेंट विजेट में बदलाव करते हैं, तो आपकी कस्टम स्टाइलिंग को हमारी रिलीज़ प्रक्रिया के हिस्से के रूप में टेस्ट किया जाएगा।

दूसरा तरीका विजेट कॉन्फ़िगरेशन में **customCSS** पैरामीटर निर्दिष्ट करना है, इस प्रकार:

[code-example-start config = {customCSS: "button { background: red; }" }; linesToHighlight = [6]; title = 'कस्टम CSS पास करना'; code-example-end]

हालाँकि, इसमें *सीमाएँ* हैं:
1. हेडर के आकार के कारण, हमारे सर्वर द्वारा अनुरोध अस्वीकार किए जाने से पहले पास की जा सकने वाली कस्टम CSS की एक सीमा है।
2. आपको अपने इंफ्रास्ट्रक्चर और बिल्ड सिस्टम में कस्टम CSS को प्रबंधित करना होगा। हालाँकि, यह एक नुकसान के बजाय फायदा भी हो सकता है।
3. इस उपयोग के मामले में कस्टम CSS को नेटवर्क पर **दो बार** भेजने का अतिरिक्त ओवरहेड होता है, क्योंकि इसे हमारे सर्वर पर भेजा जाना है, और फिर iframe कंटेंट में वापस भेजा जाना है। हालाँकि अधिकांश पेलोड आकारों के लिए यह ध्यान देने योग्य नहीं है।
4. एक सामान्य अनुकूलन नेटवर्क पर आकार कम करने के लिए CSS को minify करना है, लेकिन इस तरीके से आपको यह स्वयं संभालना होगा।
5. जब हम बदलाव करते हैं तो आपकी कस्टम CSS का टेस्ट नहीं किया जाएगा।

### बाहरी CSS फ़ाइलें

आप `@import` का उपयोग करके विजेट को एक बाहरी फ़ाइल फ़ेच करने के लिए कह सकते हैं!

यह अनुशंसा की जाती है कि `@import` को एक कस्टमाइज़ेशन रूल में रखा जाए। इस तरह, यदि हमें कभी कमेंट विजेट में बदलाव करने की आवश्यकता होती है, तो हम अपने ऑटोमेशन टूलिंग का उपयोग करके आपके सेटअप को सत्यापित कर सकते हैं। उदाहरण के लिए, आप Widget Customization UI में एक कस्टमाइज़ेशन रूल बनाएंगे, `Advanced` पर क्लिक करेंगे, और `Custom CSS` में दर्ज करेंगे:

    @import url(https://example.com/styles.css);

#### कोड में - अनुशंसित नहीं

आप `customCSS` प्रॉपर्टी के माध्यम से भी एक बाहरी CSS फ़ाइल लोड कर सकते हैं:

[code-example-start config = {customCSS: "@import url(https://example.com/styles.css);" }; linesToHighlight = [6]; title = 'बाहरी CSS फ़ाइल'; code-example-end]

हालाँकि, याद रखें कि यदि आप ऐसा करते हैं तो हम आपकी CSS का टेस्ट नहीं कर पाएंगे।

### यूज़र प्रोफ़ाइल मोडल स्टाइलिंग

यूज़र प्रोफ़ाइल मोडल को भी कस्टम CSS से स्टाइल किया जा सकता है। हालाँकि, यह सुनिश्चित करने के लिए कि कस्टम स्टाइलिंग यूज़र प्रोफ़ाइल पर लागू हो, सभी CSS सिलेक्टर के आगे `.user-profile` लगाना अनिवार्य है। इस प्रीफ़िक्स के बिना, यूज़र प्रोफ़ाइल मोडल के लिए कस्टम स्टाइलिंग को अनदेखा किया जाएगा।

उदाहरण के लिए:

[code-example-start config = {customCSS: ".user-profile .profile-name { color: blue; }" }; title = 'यूज़र प्रोफ़ाइल CSS'; code-example-end]

### पश्चगामी संगतता (Backwards Compatibility)

FastComments में, हम जानते हैं कि हमारे ग्राहक कमेंटिंग विजेट को कस्टमाइज़ करते हैं। यह डिज़ाइन द्वारा है - हम यह बिल्कुल नहीं चाहते कि हमारा उत्पाद आपके उत्पाद में डिज़ाइन विसंगतियाँ पैदा करे।

चूँकि यह हमारे उत्पाद का एक महत्वपूर्ण हिस्सा है, हमारे पास एक बिल्ड पाइपलाइन है जो हमें प्रत्येक रिलीज़ में, प्रति-ग्राहक, कमेंट विजेट में बदलावों की समीक्षा करने की अनुमति देती है।

यदि हमें छोटी समस्याएँ मिलती हैं, तो हम यह सुनिश्चित करने के लिए आपके खाते को अपडेट करेंगे कि हमारी रिलीज़ सुचारू रूप से हो। यदि हमें बड़े ब्रेकिंग बदलाव दिखते हैं, तो यह हमें रिलीज़ को रोकने की अनुमति देता है।
