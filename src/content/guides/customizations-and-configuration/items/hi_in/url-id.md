[related-parameter-start name = 'urlId'; type = 'string'; related-parameter-end]

कमेंट थ्रेड रेंडर करते समय, या कमेंट छोड़ते समय, FastComments को यह जानने की आवश्यकता होती है कि वे कमेंट किस पेज, आर्टिकल या प्रोडक्ट से संबंधित हैं।

इसके लिए, हम कुछ ऐसा उपयोग करते हैं जिसे हम "URL ID" कहते हैं। यह या तो एक पहचानकर्ता (identifier) होता है, जैसे एक स्ट्रिंग या संख्या, या एक URL।

डिफ़ॉल्ट रूप से, यदि आप urlId निर्दिष्ट नहीं करते हैं, तो यह पेज URL बन जाएगा। हम वर्तमान पेज URL लेंगे, और उसमें से किसी भी सामान्य मार्केटिंग पैरामीटर या ट्रैकिंग पहचानकर्ताओं को हटाने के लिए उसे साफ़ (clean) करेंगे।

थर्ड पार्टी इंटीग्रेशन के मामले में, जैसे WordPress, हमारा प्लगइन आमतौर पर उस पहचानकर्ता का उपयोग URL ID के रूप में करेगा जो वर्तमान में देखी जा रही जानकारी का प्रतिनिधित्व करता है, उदाहरण के लिए आर्टिकल/पेज id।

[code-example-start config = {urlId: 'https://example.com/page'}; linesToHighlight = [6]; title = 'कस्टम URL ID परिभाषित करना'; code-example-end]

एक चीज़ जिसका हम इस दस्तावेज़ में अक्सर उल्लेख करेंगे, वह है <a href="https://fastcomments.com/auth/my-account/customize-widget/new">Widget Customization UI</a>।

इस UI का उपयोग कोड का उपयोग किए बिना कमेंट विजेट में कई बदलाव करने के लिए किया जा सकता है।

कोई कस्टमाइज़ेशन नियम बनाते समय, हम अक्सर चाहते हैं कि वह हमारी साइट के सभी पेजों पर लागू हो। हालाँकि, कुछ मामलों में हम किसी विशेष पेज पर कमेंट विजेट को कस्टमाइज़ करना चाहते हैं, या तो कस्टम स्टाइलिंग लागू करने के लिए, या शायद उस विशेष पेज के लिए कमेंट को अनाम (anonymous) बनाने के लिए। उदाहरण के लिए, आप कुछ पेजों पर लाइव कमेंट को तुरंत दिखा सकते हैं, जबकि अन्य पर उन्हें नोटिफिकेशन बटन के नीचे छिपा सकते हैं।

यह सब इस पेज पर URL ID इनपुट फ़ील्ड के माध्यम से संभव है, जो निम्नानुसार दिखता है:

[app-screenshot-start url='/auth/my-account/customize-widget/new'; selector = '.url-id'; alt='URL ID फ़ील्ड जिसका उपयोग किसी कस्टमाइज़ेशन नियम को एक पेज तक, या */blog/* जैसे पैटर्न तक सीमित करने के लिए किया जाता है'; title='Widget Customization पेज में URL ID इनपुट' app-screenshot-end]

इस फ़ील्ड का मान कमेंट विजेट में पास किए गए *urlId* पैरामीटर से मेल खाना चाहिए। यदि आप चाहते हैं कि आपका कस्टमाइज़ेशन नियम *urlId* से स्वतंत्र (agnostic) हो, तो इस फ़ील्ड को खाली छोड़ दें या * दर्ज करें।

2023 से, विजेट कस्टमाइज़ेशन में `URL ID` फ़ील्ड अब पैटर्न भी स्वीकार करता है! उदाहरण के लिए आप
अपने ब्लॉग के लिए विशिष्ट स्टाइलिंग जोड़ने के लिए `*/blog/*` और अपने स्टोर के लिए विशिष्ट स्टाइलिंग के लिए `*/store/*` का उपयोग कर सकते हैं,
सब कुछ एक ही डोमेन का उपयोग करते हुए।

### सावधानियाँ (Gotchas)

1. यदि आपके पेज में हैश पैरामीटर हैं (जैसे example.com#page-1) - तो यह डिफ़ॉल्ट रूप से URL ID का हिस्सा बन जाएगा।
2. माइग्रेशन के दौरान, उदाहरण के लिए WordPress से Gatsby तक, आपको प्रारंभिक माइग्रेशन के बाद URL ID कमेंट मानों को माइग्रेट करना पड़ सकता है। इसके लिए, हमसे संपर्क करें।
