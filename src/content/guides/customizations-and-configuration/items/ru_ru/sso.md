SSO, или единый вход (single-sign-on), — это набор соглашений, позволяющих вам или вашим пользователям использовать FastComments без создания ещё одной учётной записи.

Если вы не разрешаете анонимное комментирование, для комментирования через FastComments требуется учётная запись. Мы делаем процесс регистрации очень простым — пользователю достаточно указать свой email при комментировании.
Однако мы понимаем, что даже это — лишнее трение, которого некоторые сайты хотят избежать.

Мы можем уменьшить это трение, оставив всего один процесс входа для всего вашего сайта.

### Как это получить?
В настоящее время все типы аккаунтов имеют доступ к SSO. Однако максимальное количество SSO-пользователей зависит от вашего тарифа. Как и с другими функциями, тарифы Pro и выше предоставляют прямую поддержку разработки.

Давайте сравним варианты, а затем подробно рассмотрим каждый из них.

### Миграция пользователей и комментариев

При миграции с платформы с SSO, такой как Disqus, у вас уже есть пользователи и их комментарии.

Комментарии импортируются в рамках миграции — через API, наш Import UI или службу поддержки. Import UI предпочтителен, если он поддерживает платформу, с которой
вы мигрируете, так как он включает обработку ошибок, извлечение и загрузку аватаров и медиафайлов, а также систему мониторинга пакетных заданий.

Сами пользователи добавляются автоматически при первом просмотре веток комментариев. Как альтернатива, их можно предварительно добавить через API, но эта работа не даёт
особых преимуществ.

Если комментарии импортированы, а SSO-пользователи не добавлены вручную через API, то комментарии будут автоматически перенесены в учётную запись пользователя при её
первом создании, когда он просмотрит любую ветку комментариев. После этого он сможет управлять, редактировать и удалять свои изначально написанные комментарии.

Автоматическая миграция выполняется по email или имени пользователя. Некоторые платформы не предоставляют email при экспорте, например Disqus, поэтому в этом случае мы используем имя пользователя.
- Пока вы передаёте совпадающее имя пользователя и email в SSO-полезной нагрузке, мы добавим email к отдельным объектам комментариев, чтобы уведомления и упоминания работали.

Если вы хотите импортировать комментарии и пользователей одновременно, обратитесь в поддержку, чтобы после импорта пользователей через API перенести комментарии в соответствующие учётные записи пользователей.

Итак, кратко, самый простой путь миграции:

1. Импортируйте комментарии.
   1. Аватары и другие медиафайлы переносятся автоматически при использовании Import UI в `Manage Data -> Imports`.
2. Настройте Secure или Simple SSO.
3. Позвольте миграции происходить автоматически для каждого пользователя при его первом входе.
   1. Обычно это добавляет менее секунды к времени загрузки страницы, если у пользователя менее 50 тысяч комментариев.

### Пользователи WordPress
Если вы используете наш <a href="https://wordpress.org/plugins/fastcomments/" target="_blank">плагин WordPress</a>, то писать код не нужно! Просто перейдите на страницу администрирования плагина, нажмите SSO Settings, а затем Enable.

Это запустит мастер с одной кнопкой, который создаст ваш API-ключ, отправит его в вашу установку WordPress и включит SSO. Мы объединили всё это в одно нажатие кнопки.

Обратите внимание, что если вы устанавливаете плагин впервые, вам нужно будет пройти процесс настройки, прежде чем вы увидите страницу администрирования с кнопкой SSO Settings.

#### WordPress SSO — модераторы

Обратите внимание, что в настоящее время, чтобы значок «Moderator» отображался рядом с вашими модераторами при комментировании через плагин FastComments для WordPress,
они также должны быть добавлены как модераторы в панели FastComments, и их email должен быть подтверждён.

### Пользовательские интеграции

Для пользовательских интеграций есть два варианта.

### Вариант первый — Secure SSO

С Secure SSO FastComments знает, что пользователь, комментирующий, голосующий и читающий комментарии, — реальный пользователь вашего сайта.

Пока вы создаёте корректную полезную нагрузку, пользователь всегда будет получать бесшовный опыт комментирования.

С Secure SSO полезная нагрузка SSO создаётся **на стороне сервера** с использованием аутентификации HMAC, а затем передаётся виджету **на клиенте**.

С Secure SSO учётная запись пользователя **полностью отделена** от остальной базы пользователей FastComments. Это означает, что если у нас есть два партнёра —
компания A и компания B, — у каждой может быть SSO-пользователь с именем «Bob».

#### Требования
- Базовые знания о backend-разработке.
- Базовые знания о работе с секретными API-ключами.
- Базовые знания о разработке API или серверном рендеринге.

#### Плюсы
- Безопасно.
- Бесшовный опыт комментирования.

#### Минусы
- Требуется backend-разработка.

#### Обновление данных пользователя

С Secure SSO каждый раз при передаче полезной нагрузки SSO-пользователя мы обновляем его учётную запись самой свежей информацией. Например, если
у пользователя имя `X`, а вы передаёте `Y` в полезной нагрузке SSO, его имя станет `Y`.

Если вы хотите удалить значения этим способом, установите их в `null` (не `undefined`).

#### API Secure SSO

Мы также предоставляем API для взаимодействия с SSO-пользователями. См. [документацию](/guide-api.html#sso-user-structure).

Обратите внимание, что при использовании Secure SSO пользователи автоматически создаются в фоновом режиме при загрузке страницы. Вам не нужно массово импортировать своих пользователей.

### Вариант второй — Simple SSO

Альтернатива Secure SSO — просто передать информацию о пользователе виджету комментирования.

Указание email при Simple SSO не обязательно, однако без него комментарии будут отображаться как «Unverified».

<sup>Примечание!</sup> С начала 2022 года имена пользователей с Simple SSO не должны быть уникальными на всём FastComments.com.

В идеале Simple SSO следует выбирать только при разработке на платформе, не предоставляющей доступ к backend.

#### Требования
- Базовые знания о клиентской разработке.
- Необходимо знать как минимум email пользователя.

#### Плюсы
- Просто.
- Вся активность по-прежнему проходит верификацию.
- Пользователь никогда не вводит своё имя или email.

#### Минусы
- Менее безопасно, чем Secure SSO, так как клиентская полезная нагрузка может быть подделана для выдачи себя за любого пользователя.

#### API Simple SSO

Пользователи, автоматически созданные через процесс Simple SSO, сохраняются как объекты `SSOUser`. Доступ к ним и управление ими осуществляются через API `SSOUser`. См. [документацию](/guide-api.html#sso-user-structure).
