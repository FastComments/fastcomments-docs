[related-parameter-start name = 'customCSS'; type = 'string'; related-parameter-end]

FastComments разработан с учётом возможности кастомизации. Сам виджет комментариев работает внутри iframe по соображениям безопасности, поэтому для применения пользовательских стилей необходимо воспользоваться одним из двух подходов.

Первый, самый простой подход, который мы предпочитаем, — использовать [страницу настройки виджета](https://fastcomments.com/auth/my-account/customize-widget).

На странице настройки виджета откройте раздел «Показать расширенные параметры», под которым находится область с надписью «Пользовательский CSS»:

[app-screenshot-start url='/auth/my-account/customize-widget/new'; clickSelector = '.show-advanced-option'; selector = '.custom-css'; alt='Редактор пользовательского CSS под опцией «Показать расширенные параметры» на странице настройки виджета'; title='Область ввода пользовательского CSS' app-screenshot-end]

Этот подход имеет несколько преимуществ:
1. Введённый CSS минифицируется перед отправкой пользователю, а форматирование сохраняется в интерфейсе редактирования.
2. Вы получаете все возможности UI настройки виджета, например лёгкую кастомизацию виджета комментариев для разных сайтов.
3. Когда мы вносим изменения в виджет комментариев, ваша пользовательская стилизация будет протестирована в рамках нашего процесса релиза.

Второй подход — указать параметр **customCSS** в конфигурации виджета, как показано ниже:

[code-example-start config = {customCSS: "button { background: red; }"}; linesToHighlight = [6]; title = 'Передача пользовательского CSS'; code-example-end]

Однако у этого метода есть *ограничения*:
1. Существует лимит на объём пользовательского CSS, который можно передать, прежде чем наши серверы отклонят запрос из‑за размера заголовков.
2. Вы должны управлять пользовательским CSS в своей инфраструктуре и системе сборки. Это может быть как плюсом, так и минусом.
3. При таком использовании происходит дополнительная передача пользовательского CSS по сети **дважды**: сначала к нашим серверам, затем обратно в содержимое iframe. Для большинства размеров полезной нагрузки это незаметно.
4. Часто применяется оптимизация — минификация CSS для уменьшения его размера в сети, однако при этом подходе вам придётся заниматься этим самостоятельно.
5. Ваш пользовательский CSS не будет протестирован при изменениях со стороны нашей команды.

### Внешние файлы CSS

Вы можете заставить виджет загружать внешний файл, используя `@import`!

Рекомендуется помещать `@import` в правило кастомизации. Таким образом, если нам понадобится изменить виджет комментариев, мы сможем с помощью нашей автоматизации проверить вашу настройку. Например, вы создаёте правило кастомизации в UI настройки виджета, нажимаете «Расширенные» и вводите в поле «Пользовательский CSS»:

    @import url(https://example.com/styles.css);

#### В коде — не рекомендуется

Также можно загрузить внешний CSS‑файл через свойство `customCSS`:

[code-example-start config = {customCSS: "@import url(https://example.com/styles.css);"}; linesToHighlight = [6]; title = 'Внешний CSS‑файл'; code-example-end]

Однако помните, что ваш CSS не будет протестирован нами, если вы используете этот способ.

### Стилизация модального окна профиля пользователя

Модальные окна профиля пользователя также можно стилизовать с помощью пользовательского CSS. Чтобы гарантировать применение стилей к профилям, все CSS‑селекторы должны начинаться с `.user-profile`. Без этого префикса пользовательские стили будут игнорироваться для модальных окон профиля.

Пример:

[code-example-start config = {customCSS: ".user-profile .profile-name { color: blue; }"}; title = 'CSS профиля пользователя'; code-example-end]

### Обратная совместимость

В FastComments мы знаем, что наши клиенты кастомизируют виджет комментариев. Это задумано специально — последнее, чего мы хотим, это чтобы наш продукт вызывал несоответствия в дизайне вашего продукта.

Поскольку это важная часть нашего продукта, у нас есть конвейер сборки, позволяющий нам просматривать изменения в виджете комментариев для каждого клиента при каждом релизе.

Если мы обнаружим мелкие проблемы, мы обновим ваш аккаунт, чтобы обеспечить плавный релиз. Если же мы увидим серьёзные несовместимости, это позволит нам приостановить выпуск.
