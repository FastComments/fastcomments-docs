SSO(Single Sign-On, 싱글 사인온)는 사용자 여러분이나 여러분의 사용자가 다른 계정을 새로 만들 필요 없이 FastComments를 사용할 수 있도록 해주는 일련의 규약입니다.

익명 댓글 작성을 허용하지 않는 경우, FastComments로 댓글을 작성하려면 계정이 필요합니다. 우리는 이 가입 과정을 매우 쉽게 만들었습니다. 사용자는 댓글을 작성할 때 이메일만 남기면 됩니다.
하지만 일부 사이트에서는 그마저도 피하고 싶은 추가적인 마찰 요소라는 점을 우리는 잘 이해하고 있습니다.

사이트 전체에 단 하나의 로그인 흐름만 두면 이 마찰을 줄일 수 있습니다.

### 어떻게 사용할 수 있나요?
현재 모든 계정 유형에서 SSO를 사용할 수 있습니다. 다만 최대 SSO 사용자 수는 사용 중인 패키지에 따라 다릅니다. 다른 기능과 마찬가지로 Pro 플랜 이상에서는 직접적인 개발 지원을 제공합니다.

먼저 옵션들을 비교해 본 뒤, 각각의 세부 사항을 살펴보겠습니다.

### 사용자 및 댓글 마이그레이션

Disqus처럼 SSO를 사용하는 플랫폼에서 마이그레이션하는 경우, 이미 사용자와 그들의 댓글을 보유하고 있을 것입니다.

댓글은 API, Import UI 또는 고객 지원팀을 통해 마이그레이션의 일부로 가져옵니다. 마이그레이션하는 플랫폼을 지원하는 경우에는 Import UI를 사용하는 것이 좋습니다. Import UI에는 오류 처리, 아바타 및 미디어 추출과 업로드, 배치 작업 모니터링 시스템이 포함되어 있습니다.

사용자 자체는 댓글 스레드를 처음 볼 때 자동으로 추가됩니다. 또는 API를 통해 미리 추가할 수도 있지만, 이 작업에는 큰 이점이 없습니다.

댓글을 가져왔고 SSO 사용자가 API를 통해 수동으로 추가되지 않은 경우, 사용자가 댓글 스레드를 볼 때 계정이 처음 생성되는 시점에 댓글이 자동으로 해당 사용자의 계정으로 마이그레이션됩니다. 그 후 사용자는 원래 작성한 댓글을 관리, 편집, 삭제할 수 있게 됩니다.

자동 마이그레이션은 이메일 또는 사용자 이름을 통해 수행됩니다. Disqus처럼 일부 플랫폼은 내보내기 시 이메일을 제공하지 않으므로, 이 경우 사용자 이름으로 대체합니다.
- 일치하는 사용자 이름과 SSO 페이로드에 이메일을 전달하기만 하면, 개별 댓글 객체에 이메일을 추가하여 알림과 멘션이 작동하도록 합니다.

댓글과 사용자를 한 번에 가져오고 싶다면, API를 통해 사용자를 가져온 후 지원팀과 협력하여 댓글을 사용자의 각 계정으로 마이그레이션하면 됩니다.

요약하면, 마이그레이션을 위한 가장 쉬운 방법은 다음과 같습니다:

1. 댓글을 가져옵니다.
   1. `Manage Data -> Imports`의 Import UI를 사용하면 아바타와 기타 미디어가 자동으로 마이그레이션됩니다.
2. Secure SSO 또는 Simple SSO를 설정합니다.
3. 사용자가 처음 로그인할 때 사용자별로 마이그레이션이 자동으로 진행되도록 합니다.
   1. 사용자의 댓글이 5만 개 미만인 경우 일반적으로 페이지 로드 시간에 1초 미만만 추가됩니다.

### WordPress 사용자
<a href="https://wordpress.org/plugins/fastcomments/" target="_blank">WordPress 플러그인</a>을 사용 중이라면 작성할 코드가 없습니다! 플러그인의 관리자 페이지로 이동하여 SSO Settings를 클릭한 다음 Enable을 클릭하기만 하면 됩니다.

그러면 원클릭 마법사로 이동하여 API 키를 생성하고, WordPress 설치 환경으로 전송한 뒤 SSO를 활성화합니다. 우리는 이 과정을 단 한 번의 버튼 클릭으로 통합했습니다.

플러그인을 처음 설치하는 경우에는 SSO Settings 버튼이 있는 관리자 페이지가 보이기 전에 설정 과정을 먼저 완료해야 한다는 점에 유의하세요.

#### WordPress SSO - 중재자(Moderators)

FastComments WordPress 플러그인으로 댓글을 작성할 때 중재자 옆에 "Moderator" 배지가 표시되려면, 현재로서는 해당 사용자가 FastComments 대시보드에서도 중재자(Moderator)로 추가되어 있고 이메일 인증이 완료되어 있어야 합니다.

### 커스텀 통합

커스텀 통합에는 두 가지 옵션이 있습니다.

### 옵션 1 - Secure SSO

Secure SSO를 사용하면 FastComments는 댓글을 작성하고, 투표하고, 댓글을 읽는 사용자가 여러분 사이트의 실제 사용자임을 알 수 있습니다.

유효한 페이로드를 생성하기만 하면 사용자는 항상 매끄러운 댓글 작성 경험을 누릴 수 있습니다.

Secure SSO에서는 SSO 페이로드가 HMAC 인증을 사용하여 **서버 측**에서 생성된 후 **클라이언트**의 위젯에 전달됩니다.

Secure SSO에서는 사용자의 계정이 나머지 FastComments 사용자 기반과 **완전히 분리**됩니다. 즉, Company A와 Company B라는 두 파트너가 있을 경우, 각각 사용자 이름이 "Bob"인 SSO 사용자를 가질 수 있습니다.

#### 요구 사항
- 백엔드 개발에 대한 기본적인 지식.
- 시크릿 API 키 처리에 대한 기본적인 지식.
- API 개발 또는 서버 사이드 렌더링에 대한 기본적인 지식.

#### 장점
- 안전합니다.
- 매끄러운 댓글 작성 경험.

#### 단점
- 백엔드 개발이 필요합니다.

#### 사용자 데이터 업데이트

Secure SSO에서는 sso 사용자 페이로드를 전달할 때마다 최신 정보로 사용자를 업데이트합니다. 예를 들어, 사용자의 사용자 이름이 `X`인데 SSO 페이로드에서 `Y`를 전달하면 사용자 이름이 `Y`로 변경됩니다.

이 방식으로 값을 제거하려면 `undefined`가 아닌 `null`로 설정하세요.

#### Secure SSO API

SSO 사용자와 상호 작용하기 위한 API도 제공합니다. [문서](/guide-api.html#sso-user-structure)를 참조하세요.

Secure SSO를 사용하면 페이지 로드 시 사용자가 백그라운드에서 자동으로 생성됩니다. 사용자를 대량으로 가져올 필요가 없습니다.

### 옵션 2 - Simple SSO

Secure SSO의 대안은 사용자 정보를 댓글 위젯에 직접 전달하는 것입니다.

Simple SSO에서는 이메일 제공이 필수는 아니지만, 이메일이 없으면 해당 사용자의 댓글이 "Unverified"로 표시됩니다.

<sup>참고!</sup> 2022년 초부터 Simple SSO의 사용자 이름은 FastComments.com 전체에서 고유할 필요가 없습니다.

이상적으로는 Simple SSO는 백엔드 접근 권한을 제공하지 않는 플랫폼에서 개발할 때만 선택해야 합니다.

#### 요구 사항
- 클라이언트 측 개발에 대한 기본적인 지식.
- 최소한 사용자의 이메일을 알아야 합니다.

#### 장점
- 간단합니다.
- 모든 활동이 여전히 인증됩니다.
- 사용자는 사용자 이름이나 이메일을 입력할 필요가 없습니다.

#### 단점
- 클라이언트 측 페이로드가 조작되어 어떤 사용자로도 위장될 수 있으므로 Secure SSO보다 덜 안전합니다.

#### Simple SSO API

Simple SSO 흐름을 통해 자동으로 생성된 사용자는 `SSOUser` 객체로 저장됩니다. `SSOUser` API를 통해 접근하고 관리할 수 있습니다. [문서](/guide-api.html#sso-user-structure)를 참조하세요.
