SSO(Single Sign-On、シングルサインオン)とは、あなたやあなたのユーザーが新しいアカウントを作成することなくFastCommentsを利用できるようにするための一連の規約です。

匿名コメントを許可していない場合、FastCommentsでコメントするにはアカウントが必要です。サインアッププロセスは非常に簡単にしています。ユーザーはコメント時にメールアドレスを残すだけです。
しかし、それでも余分な手間を避けたいサイトがあることは理解しています。

サイト全体でログインフローを1つにすることで、この手間を減らすことができます。

### 利用するには?
現在、すべてのアカウントタイプでSSOを利用できます。ただし、SSOユーザーの最大数はプランによって異なります。他の機能と同様に、Proプラン以上では直接の開発サポートが提供されます。

まず各オプションを比較し、その後それぞれの詳細を見ていきましょう。

### ユーザーとコメントの移行

DisqusのようなSSO対応プラットフォームから移行する場合、すでにユーザーとそのコメントが存在しています。

コメントは、API、インポートUI、またはカスタマーサポートによる移行の一部としてインポートされます。移行元のプラットフォームがサポートされている場合は、インポートUIの利用が推奨されます。インポートUIには、エラーハンドリング、アバターおよびメディアの抽出とアップロード、バッチジョブ監視システムが組み込まれています。

ユーザーそのものは、初めてコメントスレッドを表示した際に自動的に追加されます。あるいは、API経由で事前に追加することもできますが、この作業にはあまりメリットがありません。

コメントがインポートされ、SSOユーザーがAPI経由で手動追加されていない場合、ユーザーが任意のコメントスレッドを表示した際に初めてアカウントが作成されるときに、コメントは自動的にそのユーザーのアカウントに移行されます。その後、ユーザーは自分が元々書いたコメントを管理、編集、削除できるようになります。

自動移行はメールアドレスまたはユーザー名によって行われます。Disqusのように、エクスポート時にメールアドレスが提供されないプラットフォームもあるため、その場合はユーザー名にフォールバックします。
- 一致するユーザー名と、SSOペイロード内のメールアドレスを渡していただければ、通知やメンションが機能するように、個々のコメントオブジェクトにメールアドレスを追加します。

コメントとユーザーを一度にインポートしたい場合は、API経由でユーザーをインポートした後、サポートと連携してコメントを各ユーザーのアカウントに移行してください。

まとめると、移行の最も簡単な手順は以下の通りです:

1. コメントをインポートする。
   1. `Manage Data -> Imports` のインポートUIを使用する場合、アバターやその他のメディアは自動的に移行されます。
2. Secure SSOまたはSimple SSOをセットアップする。
3. ユーザーが初めてログインした際に、ユーザーごとに自動的に移行が行われるようにする。
   1. ユーザーのコメント数が5万件未満であれば、通常、ページの読み込み時間に1秒未満しか追加されません。

### WordPressユーザー
<a href="https://wordpress.org/plugins/fastcomments/" target="_blank">WordPressプラグイン</a>をご利用の場合、コードを書く必要はありません! プラグインの管理ページに移動し、SSO Settingsをクリックして、Enableをクリックするだけです。

これにより、ワンクリックのウィザードが表示され、APIキーが作成され、WordPressインストールに送信され、SSOが有効になります。この操作を1回のボタンクリックにまとめました。

プラグインを初めてインストールする場合は、SSO Settingsボタンのある管理ページが表示される前に、セットアッププロセスを完了する必要がある点にご注意ください。

#### WordPress SSO - モデレーター

FastComments WordPressプラグインでモデレーターがコメントした際に「Moderator」バッジを表示するには、現在のところ、FastCommentsダッシュボードでもモデレーターとして追加され、メールアドレスの確認が完了している必要がある点にご注意ください。

### カスタム統合

カスタム統合には2つのオプションがあります。

### オプション1 - Secure SSO

Secure SSOでは、コメント、投票、コメント閲覧を行っているユーザーが、あなたのサイトの実際のユーザーであることをFastCommentsが認識します。

有効なペイロードを作成さえすれば、ユーザーは常にシームレスなコメント体験を得られます。

Secure SSOでは、SSOペイロードはHMAC認証を使用して**サーバーサイド**で作成され、**クライアント**のウィジェットに渡されます。

Secure SSOでは、ユーザーのアカウントはFastCommentsの他のユーザーベースから**完全に分離**されています。つまり、Company AとCompany Bという2つのパートナーがいる場合、それぞれが「Bob」というユーザー名のSSOユーザーを持つことができます。

#### 必要条件
- バックエンド開発に関する基本的な知識。
- シークレットAPIキーの取り扱いに関する基本的な知識。
- API開発またはサーバーサイドレンダリングに関する基本的な知識。

#### メリット
- セキュア。
- シームレスなコメント体験。

#### デメリット
- バックエンド開発が必要。

#### ユーザーデータの更新

Secure SSOでは、SSOユーザーペイロードを渡すたびに、最新の情報でユーザーが更新されます。例えば、ユーザーのユーザー名が `X` で、SSOペイロードで `Y` を渡すと、ユーザー名は `Y` に変更されます。

この方法で値を削除したい場合は、`undefined` ではなく `null` を設定してください。

#### Secure SSO API

SSOユーザーとやり取りするためのAPIも提供しています。詳しくは[ドキュメント](/guide-api.html#sso-user-structure)をご覧ください。

Secure SSOを使用する場合、ユーザーはページ読み込み時にバックグラウンドで自動的に作成されます。ユーザーを一括インポートする必要はありません。

### オプション2 - Simple SSO

Secure SSOの代替手段として、ユーザー情報をコメントウィジェットに直接渡す方法があります。

Simple SSOではメールアドレスの提供は必須ではありませんが、提供しない場合、そのコメントは「Unverified」と表示されます。

<sup>注意!</sup> 2022年初頭以降、Simple SSOのユーザー名はFastComments.com全体で一意である必要はありません。

理想的には、Simple SSOはバックエンドアクセスを提供しないプラットフォームで開発する場合にのみ選択すべきです。

#### 必要条件
- クライアントサイド開発に関する基本的な知識。
- 少なくともユーザーのメールアドレスを知っている必要がある。

#### メリット
- シンプル。
- すべてのアクティビティは引き続き検証される。
- ユーザーはユーザー名やメールアドレスを入力する必要がない。

#### デメリット
- クライアントサイドのペイロードが細工されて任意のユーザーになり得るため、Secure SSOよりもセキュリティが低い。

#### Simple SSO API

Simple SSOフローで自動作成されたユーザーは、`SSOUser` オブジェクトとして保存されます。これらは `SSOUser` API経由でアクセスおよび管理できます。詳しくは[ドキュメント](/guide-api.html#sso-user-structure)をご覧ください。
