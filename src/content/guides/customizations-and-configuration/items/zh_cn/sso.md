SSO，即单点登录（single-sign-on），是一套约定，用于让您或您的用户无需再创建另一个账户即可使用 FastComments。

假设您不允许匿名评论，那么使用 FastComments 评论需要一个账户。我们让这个注册过程非常简单——用户只需在评论时留下他们的电子邮件即可。
不过，我们也理解，即使是这一点额外的阻力，有些网站也希望避免。

我们可以通过让整个网站只有一个登录流程来减少这种阻力。

### 如何获得该功能？
目前所有账户类型都可以使用 SSO。但是，SSO 用户数量上限取决于您的套餐。与其他功能一样，Pro 及更高版本的计划提供直接的开发支持。

让我们先比较各个选项，然后深入了解每一项。

### 用户和评论迁移

当从支持 SSO 的平台（如 Disqus）迁移时，您已经拥有用户及其评论。

评论会作为迁移的一部分被导入，可以通过 API、我们的导入 UI 或客户支持来完成。如果导入 UI 支持您要迁移的平台，则首选导入 UI，因为它包含错误处理、头像和媒体提取与上传，以及批处理任务监控系统。

用户本身会在首次查看评论线程时自动添加。或者，也可以通过 API 预先添加，但这样做并没有太多优势。

如果评论已导入，而 SSO 用户未通过 API 手动添加，那么当用户首次查看任何评论线程并创建账户时，评论会自动迁移到该用户的账户。之后他们将能够管理、编辑和删除自己最初撰写的评论。

自动迁移通过电子邮件或用户名完成。某些平台在导出时不提供电子邮件，例如 Disqus，因此在这种情况下我们会退而使用用户名。
- 只要您传入匹配的用户名，并在 SSO 载荷中提供电子邮件，我们就会将电子邮件添加到各个评论对象中，以便通知和提及功能正常工作。

如果您希望一次性导入评论和用户，可以在通过 API 导入用户后，与支持团队协作，将评论迁移到用户各自的账户。

因此，总结一下迁移最简单的路径：

1. 导入评论。
   1. 如果使用 `Manage Data -> Imports` 中的导入 UI，头像和其他媒体会自动迁移。
2. 设置 Secure SSO 或 Simple SSO。
3. 让迁移在用户首次登录时按用户自动进行。
   1. 如果用户的评论少于 5 万条，这通常只会给页面加载时间增加不到一秒。

### WordPress 用户
如果您使用我们的 <a href="https://wordpress.org/plugins/fastcomments/" target="_blank">WordPress 插件</a>，那么无需编写任何代码！只需前往插件的管理页面，点击 SSO Settings，然后点击 Enable。

这将带您进入一个单击式向导，它会创建您的 API 密钥，将其发送到您的 WordPress 安装并开启 SSO。我们已将此整合为一次按钮点击。

请注意，如果您是首次安装该插件，则需要先完成设置流程，才能看到带有 SSO Settings 按钮的管理页面。

#### WordPress SSO - 版主

请注意，目前若要在版主使用 FastComments WordPress 插件评论时在其旁边显示"Moderator"徽章，
他们还必须在 FastComments 控制面板中被添加为版主，并且其电子邮件已通过验证。

### 自定义集成

对于自定义集成，有两种选项。

### 选项一 - Secure SSO

使用 Secure SSO，FastComments 可以确认评论、投票和阅读评论的用户是您网站上的真实用户。

只要您创建有效的载荷，用户将始终拥有无缝的评论体验。

使用 Secure SSO 时，SSO 载荷是在**服务器端**使用 HMAC 身份验证创建的，然后传递给**客户端**上的小部件。

使用 Secure SSO 时，用户的账户与 FastComments 的其他用户群**完全隔离**。这意味着如果我们有两个合作伙伴
Company A 和 Company B，每一方都可以拥有一个用户名为"Bob"的 SSO 用户。

#### 要求
- 具备一些后端开发的基础知识。
- 具备一些处理私密 API 密钥的基础知识。
- 具备一些 API 开发或服务器端渲染的基础知识。

#### 优点
- 安全。
- 无缝的评论体验。

#### 缺点
- 需要后端开发。

#### 更新用户数据

使用 Secure SSO 时，每次您传递 sso 用户载荷，我们都会用最新信息更新该用户。例如，如果
用户的用户名是 `X`，而您在 SSO 载荷中传递 `Y`，则其用户名将变为 `Y`。

如果您想通过这种方式移除某个值，请将其设置为 `null`（而不是 `undefined`）。

#### Secure SSO API

我们还提供了一个用于与 SSO 用户交互的 API。请参阅[文档](/guide-api.html#sso-user-structure)。

请注意，使用 Secure SSO 时，用户会在页面加载时自动在后台创建。您无需批量导入用户。

### 选项二 - Simple SSO

Secure SSO 的替代方案是直接将用户信息传递给评论小部件。

使用 Simple SSO 时不需要提供电子邮件，但如果不提供，其评论将显示为"Unverified"。

<sup>注意！</sup> 自 2022 年初起，使用 Simple SSO 的用户名不再需要在整个 FastComments.com 上唯一。

理想情况下，只有在无法使用后端的平台上开发时，才应选择 Simple SSO。

#### 要求
- 具备一些客户端开发的基础知识。
- 至少需要知道用户的电子邮件。

#### 优点
- 简单。
- 所有活动仍会得到验证。
- 用户无需输入用户名或电子邮件。

#### 缺点
- 安全性低于 Secure SSO，因为客户端载荷可能被伪造为任意用户。

#### Simple SSO API

通过 Simple SSO 流程自动创建的用户以 `SSOUser` 对象的形式存储。可以通过 `SSOUser` API 访问和管理它们。请参阅[文档](/guide-api.html#sso-user-structure)。
