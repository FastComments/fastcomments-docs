FastComments е проектиран да бъде персонализиран. Самият уиджет за коментари работи в iframe по съображения за сигурност, така че за прилагане на
персонализирано стилизиране трябва да следвате един от два подхода.

Първият, най-лесният подход, който предпочитаме, е да използвате [страницата за персонализиране на уиджета](https://fastcomments.com/auth/my-account/customize-widget).

В страницата за персонализиране на уиджета вижте секцията "Show Advanced Options", под която има област с етикет "Custom CSS":

[app-screenshot-start url='/auth/my-account/customize-widget/new'; clickSelector = '.show-advanced-option'; selector = '.custom-css'; alt='Редактор на персонализиран CSS под Show Advanced Options на страницата за персонализиране на уиджета'; title='Област за въвеждане на персонализиран CSS' app-screenshot-end]

Този подход има някои предимства:
1. Въведеният CSS се минифицира, преди да бъде изпратен на потребителя, а форматирането се запазва последователно в интерфейса за редактиране.
2. Получавате всички предимства на интерфейса за персонализиране на уиджета, например лесно персонализиране на уиджета за коментари по различен начин за различни сайтове.
3. Когато правим промени в уиджета за коментари, вашето персонализирано стилизиране ще бъде тествано като част от нашия процес на издаване.

Вторият подход е да посочите параметъра **customCSS** в конфигурацията на уиджета, както следва:

[code-example-start config = {customCSS: "button { background: red; }" }; linesToHighlight = [6]; title = 'Подаване на персонализиран CSS'; code-example-end]

Това обаче има *ограничения*:
1. Има ограничение колко персонализиран CSS може да бъде подаден, преди нашите сървъри да отхвърлят заявката, поради размера на хедърите.
2. Трябва да управлявате персонализирания CSS в своята инфраструктура и система за изграждане. Това може да е предимство, а не недостатък.
3. Има допълнителни разходи за изпращане на персонализирания CSS по мрежата **два пъти** в този случай, тъй като той трябва да бъде изпратен до нашите сървъри, а след това обратно в съдържанието на iframe. За повечето размери на данните обаче това не се забелязва.
4. Честа оптимизация е минифицирането на CSS, за да се намали размерът му по мрежата, но с този подход ще трябва да се погрижите за това сами.
5. Вашият персонализиран CSS няма да бъде тестван, когато правим промени.

### Външни CSS файлове

Можете да укажете на уиджета да извлече външен файл, като използвате `@import`!

Препоръчително е да поставите `@import` в правило за персонализиране. По този начин, ако някога се наложи да направим промяна в уиджета за коментари, можем да използваме нашите инструменти за автоматизация, за да проверим вашата конфигурация. Например, бихте създали правило за персонализиране в интерфейса за персонализиране на уиджета, щракнете `Advanced` и въведете в `Custom CSS`:

    @import url(https://example.com/styles.css);

#### В код - Не се препоръчва

Можете също да заредите външен CSS файл чрез свойството `customCSS`:

[code-example-start config = {customCSS: "@import url(https://example.com/styles.css);" }; linesToHighlight = [6]; title = 'Външен CSS файл'; code-example-end]

Не забравяйте обаче, че вашият CSS няма да може да бъде тестван от нас, ако направите това.

### Стилизиране на модала за потребителски профил

Модалите за потребителски профил също могат да бъдат стилизирани с персонализиран CSS. За да се гарантира обаче, че персонализираното стилизиране се прилага към потребителските профили, всички CSS селектори трябва да имат префикс `.user-profile`. Без този префикс персонализираното стилизиране ще бъде игнорирано за модалите на потребителски профил.

Например:

[code-example-start config = {customCSS: ".user-profile .profile-name { color: blue; }" }; title = 'CSS за потребителски профил'; code-example-end]

### Обратна съвместимост

В FastComments знаем, че нашите клиенти персонализират уиджета за коментари. Това е по замисъл - последното, което искаме, е нашият продукт да причини несъответствия в дизайна на вашия продукт.

Тъй като това е важна част от нашия продукт, имаме изграждаща линия (build pipeline), която ни позволява да преглеждаме промените в уиджета за коментари, за всеки клиент, при всяко издание.

Ако открием дребни проблеми, ще актуализираме вашия акаунт, за да гарантираме, че изданието премине гладко. Ако видим големи разрушителни промени, това ни позволява да спрем изданието.
