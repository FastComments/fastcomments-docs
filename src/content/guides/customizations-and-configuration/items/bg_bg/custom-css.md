FastComments е проектиран да бъде персонализиран. Самият уиджет за коментари се изпълнява в iframe по причини за сигурност, така че за прилагане на персонализирано стилизиране трябва да следвате един от двата подхода.

Първият, най-лесният подход и предпочитан от нас, е да използвате [страницата за персонализиране на уиджета](https://fastcomments.com/auth/my-account/customize-widget).

В страницата за персонализиране на уиджета, вижте секцията „Показване на разширени опции“, под която има област с етикет „Персонализиран CSS“:

[app-screenshot-start url='/auth/my-account/customize-widget/new'; clickSelector = '.show-advanced-option'; selector = '.custom-css'; alt='Редактор за персонализиран CSS под „Показване на разширени опции“ на страницата за персонализиране на уиджета'; title='Област за въвеждане на персонализиран CSS' app-screenshot-end]

Този подход има някои предимства:
1. Въведеният CSS се минифицира преди да бъде изпратен на потребителя, а форматирането се запазва последователно в потребителския интерфейс за редактиране.
2. Получавате всички предимства на UI за персонализиране на уиджета, например лесно персонализиране на уиджета за коментари различно за различни сайтове.
3. Когато правим промени в уиджета за коментари, вашият персонализиран стил ще бъде тестван като част от процеса на нашия релийз.

Вторият подход е да зададете параметъра **customCSS** в конфигурацията на уиджета, както следва:

[code-example-start config = {customCSS: "button { background: red; }" }; linesToHighlight = [6]; title = 'Passing Custom CSS'; code-example-end]

Въпреки това, това има *ограничения*:
1. Съществува ограничение за количеството персонализиран CSS, което може да бъде предадено, преди нашите сървъри да отхвърлят заявката, поради размера на заглавните части.
2. Трябва да управлявате персонализирания CSS във вашата инфраструктура и система за изграждане. Това може също да бъде предимство, а не недостатък.
3. Има допълнително натоварване при изпращане на персонализирания CSS по мрежата **два пъти** в този случай, тъй като трябва да бъде изпратен към нашите сървъри и след това обратно в съдържанието на iframe. Въпреки това за повечето размери на полезния товар това не се забелязва.
4. Често използвана оптимизация е минифициране на CSS, за да се намали размерът му по мрежата, но с този подход вие ще трябва да се справите с това.
5. Вашият персонализиран CSS няма да бъде тестван, когато правим промени.

### External CSS Files

Можете да укажете на уиджета да зареди външен файл, като използвате `@import`!

Препоръчително е да поставите `@import` в правило за персонализиране. По този начин, ако някога се наложи да направим промяна в уиджета за коментари, можем да използваме нашите автоматизирани инструменти, за да проверим вашата настройка. Например, ще създадете правило за персонализиране в UI за персонализиране на уиджета, кликнете върху `Advanced` и въведете в `Custom CSS`:

    @import url(https://example.com/styles.css);

#### In Code - Not Recommended

Можете също да заредите външен CSS файл чрез свойството `customCSS`:

[code-example-start config = {customCSS: "@import url(https://example.com/styles.css);" }; linesToHighlight = [6]; title = 'External CSS File'; code-example-end]

Въпреки това, имайте предвид, че вашият CSS няма да може да бъде тестван от нас, ако направите това. 

### User Profile Modal Styling

Модалните прозорци за потребителски профил също могат да бъдат стилизирани с персонализиран CSS. Въпреки това, за да се гарантира, че персонализираното стилизиране се прилага към потребителските профили, всички CSS селектори трябва да бъдат с префикс `.user-profile`. Без този префикс персонализираното стилизиране ще бъде игнорирано за модалните прозорци на потребителския профил.

Например:

[code-example-start config = {customCSS: ".user-profile .profile-name { color: blue; }" }; title = 'User Profile CSS'; code-example-end]

### Backwards Compatibility

В FastComments знаем, че нашите клиенти персонализират уиджета за коментари. Това е по замисъл – последното, което искаме, е нашият продукт да предизвика несъответствия в дизайна на вашия продукт.

Тъй като това е важна част от нашия продукт, имаме процес за изграждане, който ни позволява да преглеждаме промените в уиджета за коментари, за всеки клиент, при всеки релийз.

Ако открием малки проблеми, ще актуализираме вашия акаунт, за да осигурим гладкото протичане на нашия релийз. Ако видим големи, разрушителни промени, това ни позволява да спрем релийза.
