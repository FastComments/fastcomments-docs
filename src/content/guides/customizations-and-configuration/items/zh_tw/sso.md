SSO,即單一登入,是一套約定,讓您或您的使用者無需再建立另一個帳號即可使用 FastComments。

假設您不允許匿名留言,則使用 FastComments 留言需要一個帳號。我們讓這個註冊過程非常簡單——使用者留言時只需留下電子郵件即可。
然而,我們理解即使是這樣,有些網站也想避免這種額外的阻礙。

我們可以透過讓整個網站只有一個登入流程來減少這種阻礙。

### 如何取得?
目前所有帳號類型都可使用 SSO。但是,SSO 使用者的最大數量會依您的方案而有所不同。與其他功能一樣,Pro 及更高方案提供直接的開發支援。

讓我們比較各種選項,然後深入探討每個選項的細節。

### 使用者與留言遷移

當從支援 SSO 的平台(如 Disqus)遷移時,您已經擁有使用者及其留言。

留言會作為遷移的一部分被匯入,無論是透過 API、我們的匯入 UI,還是客戶支援。如果匯入 UI 支援您要遷移的平台,則建議使用匯入 UI,因為它包含錯誤處理、頭像與媒體的擷取與上傳,以及批次作業監控系統。

使用者本身會在首次檢視留言串時自動新增。或者,也可以透過 API 預先新增,但這樣做並沒有太多好處。

如果留言已匯入,而 SSO 使用者未透過 API 手動新增,則留言會在使用者首次檢視任何留言串並建立帳號時自動遷移到該使用者的帳號。之後他們將能夠管理、編輯和刪除他們最初撰寫的留言。

自動遷移是透過電子郵件或使用者名稱完成的。有些平台在匯出時不提供電子郵件,例如 Disqus,因此在這種情況下我們會退而使用使用者名稱。
- 只要您在 SSO 負載中傳遞相符的使用者名稱和電子郵件,我們就會將電子郵件新增到各個留言物件中,以便通知和提及功能正常運作。

如果您希望一次匯入留言和使用者,請與支援團隊合作,在使用者透過 API 匯入後,將留言遷移到使用者各自的帳號。

因此,總結最簡單的遷移路徑如下:

1. 匯入留言。
   1. 如果使用 `Manage Data -> Imports` 中的匯入 UI,頭像和其他媒體會自動遷移。
2. 設定 Secure 或 Simple SSO。
3. 讓遷移在使用者首次登入時自動逐個使用者進行。
   1. 如果使用者的留言少於 5 萬條,這通常只會為頁面載入時間增加不到一秒。

### 自訂整合

對於自訂整合,有兩種選項。

### 選項一 - Secure SSO

使用 Secure SSO,FastComments 會知道留言、投票和閱讀留言的使用者是您網站上的真實使用者。

只要您建立有效的負載,使用者將始終擁有無縫的留言體驗。

使用 Secure SSO 時,SSO 負載是在**伺服器端**使用 HMAC 驗證建立的,然後傳遞給**客戶端**上的小工具。

使用 Secure SSO 時,使用者的帳號與 FastComments 的其他使用者群**完全分開**。這意味著如果我們有兩個合作夥伴
A 公司和 B 公司,每家公司都可以擁有一個使用者名稱為「Bob」的 SSO 使用者。

#### 需求
- 對後端開發有基本了解。
- 對處理機密 API 金鑰有基本了解。
- 對 API 開發或伺服器端渲染有基本了解。

#### 優點
- 安全。
- 無縫的留言體驗。

#### 缺點
- 需要後端開發。

#### 更新使用者資料

使用 Secure SSO 時,每次您傳遞 SSO 使用者負載時,我們都會用最新資訊更新該使用者。例如,如果
使用者有一個使用者名稱 `X`,而您在 SSO 負載中傳遞 `Y`,他們的使用者名稱將變成 `Y`。

如果您想使用此方法移除值,請將其設為 `null`(而不是 `undefined`)。

#### Secure SSO API

我們還提供用於與 SSO 使用者互動的 API。請參閱[文件](/guide-api.html#sso-user-structure)。

請注意,使用 Secure SSO 時,使用者會在頁面載入時自動在幕後建立。您無需批次匯入使用者。

### 選項二 - Simple SSO

Secure SSO 的替代方案是直接將使用者資訊傳遞給留言小工具。

使用 Simple SSO 時不需要提供電子郵件,但如果沒有提供,他們的留言將顯示為「Unverified」。

<sup>注意!</sup> 自 2022 年初起,使用 Simple SSO 的使用者名稱不再需要在整個 FastComments.com 上唯一。

理想情況下,只有在開發不提供後端存取權限的平台時,才應選擇 Simple SSO。

#### 需求
- 對客戶端開發有基本了解。
- 必須至少知道使用者的電子郵件。

#### 優點
- 簡單。
- 所有活動仍會被驗證。
- 使用者永遠不需要輸入使用者名稱或電子郵件。

#### 缺點
- 比 Secure SSO 不安全,因為客戶端負載可能被偽造成任何使用者。

#### Simple SSO API

透過 Simple SSO 流程自動建立的使用者會以 `SSOUser` 物件儲存。它們可以透過 `SSOUser` API 存取和管理。請參閱[文件](/guide-api.html#sso-user-structure)。
