FastComments надає просте у використанні рішення SSO. Оновлення інформації користувача за допомогою інтеграції на основі HMAC настільки ж просте, як завантаження користувачем сторінки з оновленим payload.

Проте може бути бажано керувати користувачем поза цим потоком, щоб підвищити узгодженість вашого застосунку.

SSO User API надає спосіб виконувати CRUD-операції з об'єктами, які ми називаємо SSOUsers. Ці об'єкти відрізняються від звичайних Users і зберігаються окремо для типобезпеки.

Структура об'єкта SSOUser виглядає так:

[inline-code-attrs-start title = 'Структура SSOUser'; type = 'typescript'; isFunctional = false; inline-code-attrs-end]
[inline-code-start]
interface SSOUser {
    id: string
    username: string
    email?: string
    websiteUrl?: string
    signUpDate: number
    createdFromUrlId?: string
    loginCount?: number
    avatarSrc?: string
    optedInNotifications?: boolean
    optedInSubscriptionNotifications?: boolean
    displayLabel?: string
    displayName?: string
    isAccountOwner?: boolean // Права адміністратора - SSO-користувачі з цим прапорцем тарифікуються як SSO Admins (окремо від звичайних SSO-користувачів)
    isAdminAdmin?: boolean // Права адміністратора - SSO-користувачі з цим прапорцем тарифікуються як SSO Admins (окремо від звичайних SSO-користувачів)
    isCommentModeratorAdmin?: boolean // Права модератора - SSO-користувачі з цим прапорцем тарифікуються як SSO Moderators (окремо від звичайних SSO-користувачів)
    /** Якщо null, контроль доступу не застосовуватиметься до користувача. Якщо порожній список, цей користувач не зможе бачити жодних сторінок або @mention інших користувачів. **/
    groupIds?: string[] | null
    createdFromSimpleSSO?: boolean
    /** Не дозволяти іншим користувачам бачити активність цього користувача, включно з коментарями, у його профілі. За замовчуванням true для безпечних профілів. **/
    isProfileActivityPrivate?: boolean
    /** Не дозволяти іншим користувачам залишати коментарі в профілі користувача або бачити наявні коментарі профілю. За замовчуванням false. **/
    isProfileCommentsPrivate?: boolean
    /** Не дозволяти іншим користувачам надсилати прямі повідомлення цьому користувачу. За замовчуванням false. **/
    isProfileDMDisabled?: boolean
    karma?: number
    /** Необов'язкова конфігурація бейджів користувача. **/
    badgeConfig?: {
        /** Масив ID бейджів для призначення користувачу. Обмежено 30 бейджами. Порядок зберігається. Це глобальні бейджі, видимі на всіх сторінках. **/
        badgeIds: string[]
        /** Масив ID бейджів, обмежених поточною сторінкою (urlId). Ці бейджі відображаються лише на сторінці, де вони були призначені. **/
        pageBadgeIds?: string[]
        /** Якщо true, замінює всі наявні відображувані бейджі на надані. Глобальні бейджі та бейджі сторінок замінюються незалежно. Якщо false, додає до наявних бейджів. **/
        override?: boolean
        /** Якщо true, оновлює властивості відображення бейджів із конфігурації тенанта. **/
        update?: boolean
    }
}

### Тарифікація SSO-користувачів

SSO-користувачі тарифікуються по-різному залежно від їхніх прапорців прав:

- **Звичайні SSO-користувачі**: користувачі без прав адміністратора або модератора тарифікуються як звичайні SSO-користувачі
- **SSO Admins**: користувачі з прапорцями `isAccountOwner` або `isAdminAdmin` тарифікуються окремо як SSO Admins (за тим самим тарифом, що й звичайні адміністратори тенанта)
- **SSO Moderators**: користувачі з прапорцем `isCommentModeratorAdmin` тарифікуються окремо як SSO Moderators (за тим самим тарифом, що й звичайні модератори)

**Важливо**: щоб запобігти подвійній тарифікації, система автоматично дедуплікує SSO-користувачів щодо звичайних користувачів і модераторів тенанта за адресою електронної пошти. Якщо SSO-користувач має таку саму електронну пошту, як звичайний користувач або модератор тенанта, він не буде тарифікований двічі.

### Контроль доступу

Користувачів можна розбивати на групи. Саме для цього призначено поле `groupIds`, і воно є необов'язковим.

### @Mentions

За замовчуванням `@mentions` використовуватимуть `username` для пошуку інших sso-користувачів, коли вводиться символ `@`. Якщо використовується `displayName`, то результати, що збігаються з `username`, ігноруватимуться, коли є збіг для `displayName`, а результати пошуку `@mention` використовуватимуть `displayName`.

### Підписки

У FastComments користувачі можуть підписатися на сторінку, натиснувши на іконку дзвіночка у віджеті коментарів і обравши «Subscribe».

Для звичайного користувача ми надсилаємо йому email-сповіщення на основі його налаштувань сповіщень.

Для SSO-користувачів ми розділили це для зворотної сумісності. Користувачі отримають ці додаткові email-сповіщення про підписку, лише якщо ви встановите `optedInSubscriptionNotifications` у `true`.

### Бейджі

Ви можете призначати бейджі SSO-користувачам за допомогою властивості `badgeConfig`. Бейджі — це візуальні індикатори, що з'являються поруч з ім'ям користувача в коментарях.

- `badgeIds` - Масив ID бейджів для призначення користувачу. Це глобальні бейджі, видимі на всіх сторінках. Мають бути дійсними ID бейджів, створеними у вашому обліковому записі FastComments. Обмежено 30 бейджами.
- `pageBadgeIds` - Необов'язковий масив ID бейджів, обмежених поточною сторінкою (`urlId`). Ці бейджі відображаються лише на сторінці, де вони були призначені. Різні сторінки можуть мати різні бейджі сторінок для одного користувача.
- `override` - Якщо true, усі наявні відображувані бейджі буде замінено на надані. Глобальні бейджі та бейджі сторінок замінюються незалежно — заміна глобальних бейджів не впливає на бейджі сторінок, і навпаки. Якщо false або не вказано, надані бейджі буде додано до наявних.
- `update` - Якщо true, властивості відображення бейджів оновлюватимуться з конфігурації тенанта щоразу, коли користувач входить у систему.
