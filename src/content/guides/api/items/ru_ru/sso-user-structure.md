FastComments предоставляет простое в использовании решение SSO. Обновление информации о пользователе при интеграции на основе HMAC так же просто, как загрузка пользователем страницы с обновлённым payload.

Однако может быть желательно управлять пользователем вне этого процесса, чтобы улучшить согласованность вашего приложения.

SSO User API предоставляет способ выполнять CRUD-операции над объектами, которые мы называем SSOUsers. Эти объекты отличаются от обычных Users и хранятся отдельно для типобезопасности.

Структура объекта SSOUser выглядит следующим образом:

[inline-code-attrs-start title = 'Структура SSOUser'; type = 'typescript'; isFunctional = false; inline-code-attrs-end]
[inline-code-start]
interface SSOUser {
    id: string
    username: string
    email?: string
    websiteUrl?: string
    signUpDate: number
    createdFromUrlId?: string
    loginCount?: number
    avatarSrc?: string
    optedInNotifications?: boolean
    optedInSubscriptionNotifications?: boolean
    displayLabel?: string
    displayName?: string
    isAccountOwner?: boolean // Права администратора - SSO-пользователи с этим флагом тарифицируются как SSO Admins (отдельно от обычных SSO-пользователей)
    isAdminAdmin?: boolean // Права администратора - SSO-пользователи с этим флагом тарифицируются как SSO Admins (отдельно от обычных SSO-пользователей)
    isCommentModeratorAdmin?: boolean // Права модератора - SSO-пользователи с этим флагом тарифицируются как SSO Moderators (отдельно от обычных SSO-пользователей)
    /** Если null, контроль доступа не применяется к пользователю. Если пустой список, этот пользователь не сможет видеть никакие страницы и @mention других пользователей. **/
    groupIds?: string[] | null
    createdFromSimpleSSO?: boolean
    /** Не позволять другим пользователям видеть активность этого пользователя, включая комментарии, в его профиле. По умолчанию true для обеспечения безопасности профилей. **/
    isProfileActivityPrivate?: boolean
    /** Не позволять другим пользователям оставлять комментарии в профиле пользователя или видеть существующие комментарии профиля. По умолчанию false. **/
    isProfileCommentsPrivate?: boolean
    /** Не позволять другим пользователям отправлять прямые сообщения этому пользователю. По умолчанию false. **/
    isProfileDMDisabled?: boolean
    karma?: number
    /** Необязательная конфигурация бейджей пользователя. **/
    badgeConfig?: {
        /** Массив ID бейджей для назначения пользователю. Ограничено 30 бейджами. Порядок соблюдается. Это глобальные бейджи, видимые на всех страницах. **/
        badgeIds: string[]
        /** Массив ID бейджей, привязанных к текущей странице (urlId). Эти бейджи отображаются только на странице, где они были назначены. **/
        pageBadgeIds?: string[]
        /** Если true, заменяет все существующие отображаемые бейджи на предоставленные. Глобальные и привязанные к странице бейджи переопределяются независимо. Если false, добавляет к существующим бейджам. **/
        override?: boolean
        /** Если true, обновляет свойства отображения бейджей из конфигурации тенанта. **/
        update?: boolean
    }
}

### Тарификация SSO-пользователей

SSO-пользователи тарифицируются по-разному в зависимости от их флагов прав:

- **Обычные SSO-пользователи**: пользователи без прав администратора или модератора тарифицируются как обычные SSO-пользователи
- **SSO Admins**: пользователи с флагами `isAccountOwner` или `isAdminAdmin` тарифицируются отдельно как SSO Admins (по тому же тарифу, что и обычные администраторы тенанта)
- **SSO Moderators**: пользователи с флагом `isCommentModeratorAdmin` тарифицируются отдельно как SSO Moderators (по тому же тарифу, что и обычные модераторы)

**Важно**: для предотвращения двойной тарификации система автоматически дедуплицирует SSO-пользователей против обычных пользователей и модераторов тенанта по адресу электронной почты. Если у SSO-пользователя тот же email, что у обычного пользователя или модератора тенанта, он не будет тарифицирован дважды.

### Контроль доступа

Пользователи могут быть разбиты на группы. Для этого предназначено поле `groupIds`, и оно является необязательным.

### @Упоминания

По умолчанию `@mentions` используют `username` для поиска других sso-пользователей при вводе символа `@`. Если используется `displayName`, то результаты, совпадающие с `username`, будут игнорироваться при наличии совпадения с `displayName`, а результаты поиска `@mention` будут использовать `displayName`.

### Подписки

В FastComments пользователи могут подписаться на страницу, нажав на иконку колокольчика в виджете комментариев и выбрав «Подписаться».

Для обычного пользователя мы отправляем уведомления по электронной почте на основе его настроек уведомлений.

Для SSO-пользователей мы разделили это для обратной совместимости. Пользователи будут получать эти дополнительные письма с уведомлениями о подписке только если вы установите `optedInSubscriptionNotifications` в `true`.

### Бейджи

Вы можете назначать бейджи SSO-пользователям с помощью свойства `badgeConfig`. Бейджи — это визуальные индикаторы, отображаемые рядом с именем пользователя в комментариях.

- `badgeIds` — массив ID бейджей для назначения пользователю. Это глобальные бейджи, видимые на всех страницах. Должны быть действительными ID бейджей, созданными в вашем аккаунте FastComments. Ограничено 30 бейджами.
- `pageBadgeIds` — необязательный массив ID бейджей, привязанных к текущей странице (`urlId`). Эти бейджи отображаются только на странице, где они были назначены. Разные страницы могут иметь разные бейджи, привязанные к странице, для одного и того же пользователя.
- `override` — если true, все существующие отображаемые бейджи будут заменены на предоставленные. Глобальные и привязанные к странице бейджи переопределяются независимо — переопределение глобальных бейджей не влияет на бейджи, привязанные к странице, и наоборот. Если false или не указано, предоставленные бейджи будут добавлены к существующим.
- `update` — если true, свойства отображения бейджей будут обновляться из конфигурации тенанта при каждом входе пользователя.
