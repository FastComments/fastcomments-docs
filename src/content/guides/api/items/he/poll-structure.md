A `Poll` מצורף לתגובה, במקום להיות אובייקט נפרד. הוא נוצר יחד עם התגובה (ראו `POST /api/v1/comments`), או מתווסף לתגובה קיימת מאוחר יותר באמצעות `PUT /api/v1/polls/:commentId`.

ספירות ההצבעות נשמרות על הסקר עצמו, ולכן קריאת סקר מספקת את התוצאות מבלי צורך לסכם משהו. ההצבעות הפרטיות שמאחורי הספירות הן אובייקטים מסוג `PollVote`.

לכל אפשרות יש `id` שנוצר בעת יצירת הסקר. ה‑id הזה הוא מה שמשמש להצביע, לשנות תווית של אפשרות, ולשמור אפשרות (והצבעותיה) כאשר אתה מבצע `PUT` לסקר עם אפשרויות שנוספו או הוסרו. זו הדרך הבטוחה היחידה להתייחס לאפשרות – לעולם לא למיקומה ברשימה.

[inline-code-attrs-start title = 'מבנה סקר'; type = 'typescript'; isFunctional = false; inline-code-attrs-end]
[inline-code-start]
interface CommentPollOption {
    id: string
    label: string
    votes: number
}

interface CommentPoll {
    question: string
    options: CommentPollOption[]
    totalVotes: number
    /** כאשר מוגדר ובקודמת, הסקר נסגר ולא מקבל עוד הצבעות. **/
    closesAt?: string | null
    /** 0 אנונימי (ברירת המחדל), 1 מנהלים ומפקחים, 2 כולם. אם לא מצוין, המשמעות היא אנונימי. **/
    privacy?: 0 | 1 | 2 | null
    /** כאשר true, הספירות מוסתרות מכל מי שעדיין לא הצביע. אם לא מצוין, המשמעות היא false. **/
    requireVoteToSeeResults?: boolean | null
}
[inline-code-end]

### מגבלות

- שאלה נדרשת, ובאורך מרבי של 200 תווים.
- לסקר יש בין 2 ל‑10 אפשרויות.
- תווית אפשרות נדרשת, באורך מרבי של 100 תווים, וחייבת להיות ייחודית בתוך הסקר (בלי להתחשב ברישיות).
- `closesAt` חייב להיות בעתיד כאשר הסקר נוצר. כדי לסגור סקר מיידית, יש לבצע `PATCH` עם תאריך בעבר.

### הגדרות אתר

הסקרים מצייתים להגדרות האתר שלך, שניתן לשנות תחת Customize Widget:

- הסקרים חייבים להיות מופעלים לפני שניתן ליצור סקר, אחרת ה‑API מחזיר `polls-disabled`.
- הצבעה יכולה להיות מוגבלת למשתמשים מחוברים, ובמקרה זה הצבעה שנשלחת רק עם `anonUserId` תידחה עם `poll-login-required`.
