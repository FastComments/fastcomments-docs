### 실시간 업데이트

Collab Chat은 WebSocket 연결을 사용하여 모든 연결된 사용자 간에 모든 대화를 실시간으로 동기화합니다. 누군가 새 주석을 만들거나, 댓글을 추가하거나, 토론을 삭제하면 같은 페이지를 보고 있는 다른 모든 사용자가 새로고침 없이 즉시 업데이트를 확인할 수 있습니다.

### WebSocket 동기화 작동 방식

Collab Chat을 초기화하면 위젯이 FastComments 서버와 WebSocket 연결을 설정합니다. 이 연결은 사용자 세션 동안 열려 있으며 현재 페이지와 관련된 업데이트를 수신합니다.

WebSocket 시스템은 Collab Chat을 위해 세 가지 유형의 브로드캐스트 메시지를 사용합니다. `new-text-chat` 이벤트는 누군가 페이지에 새 주석을 만들 때 발생합니다. `updated-text-chat` 이벤트는 누군가 기존 대화를 업데이트할 때 발생합니다. `deleted-text-chat` 이벤트는 누군가 주석을 삭제할 때 발생합니다.

### 브로드캐스트 ID 시스템

사용자가 자신의 작업이 다시 자신에게 브로드캐스트되는 에코 현상을 방지하기 위해, 각 업데이트에는 고유한 `broadcastId`가 포함됩니다. 사용자가 주석을 만들거나 업데이트하면 클라이언트가 해당 작업에 대한 UUID를 생성합니다. WebSocket이 업데이트를 모든 클라이언트에 브로드캐스트하면, 원래 클라이언트는 자신의 `broadcastId`와 일치하기 때문에 해당 업데이트를 무시합니다.

이를 통해 사용자는 서버를 왕복하는 것을 기다리지 않고 UI에서 자신의 변경 사항을 즉시 확인할 수 있으며, 동시에 다른 모든 사용자도 업데이트를 받을 수 있습니다.

### 실시간 사용자 수

상단 바에는 현재 페이지를 보고 있는 사용자 수가 표시됩니다. 이 수치는 사용자가 참여하거나 떠날 때 실시간으로 업데이트됩니다. 사용자 수는 동일한 WebSocket 연결을 통해 제공되며 연결 및 연결 해제 이벤트에 따라 자동으로 증가/감소합니다.

### 연결 복원력

네트워크 문제나 서버 유지 보수로 인해 WebSocket 연결이 끊어지면 위젯이 자동으로 재연결을 시도합니다. 재연결 기간 동안 사용자는 기존 주석과 계속 상호 작용할 수 있지만, 연결이 다시 설정될 때까지 다른 사용자의 실시간 업데이트는 볼 수 없습니다.

재연결되면 위젯이 재동기화하여 누락된 업데이트가 없도록 합니다. 이 과정은 사용자 개입 없이 투명하게 이루어집니다.

### 대역폭 고려 사항

WebSocket 메시지는 가볍고 상태를 동기화하는 데 필요한 필수 정보만 포함합니다. 새 주석을 만드는 데는 일반적으로 1KB 미만의 대역폭이 사용됩니다. 또한 시스템에는 활동이 많은 기간 동안 메시지 빈도를 줄이기 위한 지능형 배칭이 포함되어 있습니다.

FastComments 대시보드의 사용량 지표에서 `pubSubMessageCount`와 `pubSubBandwidth`를 추적하여 사이트 전반의 실시간 동기화 활동을 모니터링할 수 있습니다.

### 크로스 탭 동기화

사용자가 같은 페이지를 여러 브라우저 탭에서 열어 두면, 한 탭의 업데이트가 다른 탭에 즉시 나타납니다. 이는 동일한 WebSocket 동기화 메커니즘을 통해 작동하며 추가 설정이 필요하지 않습니다.

### 보안

WebSocket 메시지는 보안 연결(WSS)을 통해 전송되며, 테넌트 검증을 포함하여 사용자가 승인된 대화의 업데이트만 수신하도록 보장합니다. 서버는 무단 접근이나 조작을 방지하기 위해 모든 작업을 브로드캐스트하기 전에 검증합니다.
