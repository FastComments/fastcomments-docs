### 即時更新

Collab Chat 使用 WebSocket 連線在所有已連線的使用者之間即時同步所有對話。當有人建立新註解、新增留言或刪除討論時，所有正在檢視同一頁面的其他使用者都會立即看到更新，無需重新整理。

### WebSocket 同步的運作方式

當您初始化 Collab Chat 時，小工具會建立與 FastComments 伺服器的 WebSocket 連線。此連線在使用者工作階段期間保持開啟，並監聽與目前頁面相關的更新。

WebSocket 系統為 Collab Chat 使用三種類型的廣播訊息。`new-text-chat` 事件在有人於頁面上建立新註解時觸發。`updated-text-chat` 事件在有人更新現有對話時觸發。`deleted-text-chat` 事件在有人刪除註解時觸發。

### 廣播 ID 系統

為了防止使用者看到自己的操作被廣播回來的回音效應，每次更新都包含一個唯一的 `broadcastId`。當使用者建立或更新註解時，其用戶端會為該操作產生一個 UUID。當 WebSocket 將更新廣播回所有用戶端時，發起操作的用戶端會因為該更新與自己的 `broadcastId` 相符而忽略它。

這確保了流暢的互動體驗：使用者可以立即在 UI 中看到自己的變更，而無需等待透過伺服器的往返過程，同時仍能確保所有其他使用者收到該更新。

### 線上人數統計

頂部列會顯示目前正在檢視該頁面的使用者人數。此人數會隨著使用者加入與離開而即時更新。使用者人數透過相同的 WebSocket 連線提供，並根據連線與斷線事件自動增減。

### 連線韌性

如果 WebSocket 連線因網路問題或伺服器維護而中斷，小工具會自動嘗試重新連線。在重新連線期間，使用者仍可與現有註解互動，但在連線重新建立之前，他們不會看到來自其他使用者的即時更新。

重新連線後，小工具會重新同步以確保沒有遺漏任何更新。此過程完全透明，無需使用者介入。

### 頻寬考量

WebSocket 訊息非常輕量，僅包含同步狀態所需的必要資訊。建立新註解通常使用不到 1KB 的頻寬。系統還包含智慧批次處理，以在高活動期間降低訊息頻率。

FastComments 儀表板中的使用量指標會追蹤 `pubSubMessageCount` 和 `pubSubBandwidth`，讓您可以監控各網站的即時同步活動。

### 跨分頁同步

如果使用者在多個瀏覽器分頁中開啟同一頁面，其中一個分頁的更新會立即出現在其他分頁中。這透過相同的 WebSocket 同步機制運作，不需要任何額外設定。

### 安全性

WebSocket 訊息透過安全連線（WSS）傳輸，並包含租戶驗證，以確保使用者僅收到其有權查看的對話更新。伺服器會在廣播之前驗證所有操作，以防止未經授權的存取或操縱。
