### 文字選取的運作方式

當使用者在 Collab Chat 容器內選取文字時，小工具會擷取該選取範圍，並允許使用者開始討論。選取範圍可以小到單一單字，也可以大到橫跨不同元素的多個段落。

### 選取延遲

在桌面裝置上，使用者選取文字與討論提示出現之間有 3.5 秒的延遲。這是為了避免使用者只是想反白文字以複製或閱讀時，UI 出現閃爍。在行動裝置上，提示會立即出現，因為在觸控螢幕上選取文字通常是刻意的行為。


### 唯一對話 ID

每個對話都會取得一個唯一的 `urlId`，由頁面 URL、DOM 元素路徑以及序列化的文字範圍組合而成。這確保每次文字選取都會建立一個獨特的對話，日後可以再次找到。

如果您在設定中提供自訂的 `urlId`，它會與元素路徑及文字範圍結合，產生最終的識別碼。

### 視覺化醒目提示

當特定文字選取範圍已有對話存在時，該文字會顯示視覺化醒目提示。醒目提示是使用背景顏色實作，並在滑鼠懸停或相關聊天視窗開啟時顯示。

醒目提示系統的運作方式是將選取的文字包覆在一個可以設定樣式的特殊元素中。這種做法可確保即使底層 HTML 結構複雜，醒目提示仍能保持準確。

### 聊天視窗定位

當使用者點擊醒目提示或建立新註解時，聊天視窗會出現在選取文字附近。小工具會根據可用的視窗空間自動計算此視窗的最佳位置。

定位系統使用 `to-right`、`to-left`、`to-top` 和 `to-bottom` 等 CSS 類別，來指示聊天視窗應從醒目提示向哪個方向延伸。在行動裝置上（寬度低於 768px 的螢幕），聊天視窗一律以全螢幕顯示，以提升可用性。

### 聊天視窗尺寸

在桌面上，聊天視窗寬度為 410px，間距為 20px，並有一個 16px 的視覺箭頭指向醒目提示的文字。這些尺寸是固定的，以確保行為一致，但您可以透過 CSS 自訂外觀。

### 跨元素選取

使用者可以選取橫跨多個 HTML 元素的文字，例如從一個段落的中間反白到另一個段落的開頭。範圍序列化系統能正確處理這種情況，即使跨越元素邊界，也會醒目提示所有選取的文字。

### 瀏覽器相容性

文字選取系統使用標準的 `window.getSelection()` API，所有現代瀏覽器都支援此 API。對於較舊版本的 Internet Explorer，它會改用 `document.selection` 以維持相容性。

### 選取範圍的持久性

一旦為文字選取範圍建立了對話，即使頁面重新載入，該註解仍會持續存在。序列化的範圍與 DOM 路徑讓小工具能在使用者返回頁面時，於完全相同的位置還原醒目提示。

只要您的頁面內容保持穩定，這項功能就能可靠運作。如果您變更文字內容或重組 HTML，現有的註解可能無法再正確對應到文字。因此，建議避免在含有有效註解的頁面上進行重大內容變更，或在必要時於內容變更時考慮遷移註解。
