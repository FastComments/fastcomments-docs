### 文本选择的工作原理

当用户在 Collab Chat 容器内选择文本时，组件会捕获该选择并允许他们发起讨论。选择范围可以小到一个单词，也可以大到跨越不同元素的多个段落。

### 选择延迟

在桌面设备上，用户选择文本到讨论提示出现之间有 3.5 秒的延迟。这可以防止用户仅仅为了复制或阅读而高亮文本时 UI 闪烁。在移动设备上，提示会立即出现，因为触摸屏上的文本选择通常更有意图性。


### 唯一的会话 ID

每个会话都会获得一个唯一的 `urlId`，它由页面 URL、DOM 元素路径和序列化的文本范围组合而成。这确保每次文本选择都会创建一个独特的会话，以后可以再次找到。

如果您在配置中提供了自定义的 `urlId`，它将与元素路径和文本范围组合以创建最终的标识符。

### 视觉高亮

当某个文本选择存在讨论时，该文本会获得视觉高亮。高亮通过背景颜色实现，并在悬停或关联的聊天窗口打开时显示。

高亮系统的工作原理是将选定的文本包裹在一个可以设置样式的特殊元素中。这种方法确保即使底层 HTML 结构复杂，高亮也能保持准确。

### 聊天窗口定位

当用户点击高亮或创建新批注时，聊天窗口会出现在选定文本附近。组件会根据可用的视口空间自动计算该窗口的最佳位置。

定位系统使用 `to-right`、`to-left`、`to-top` 和 `to-bottom` 等 CSS 类来指示聊天窗口应从高亮处向哪个方向延伸。在移动设备上（屏幕宽度小于 768px），聊天窗口始终全屏显示以获得更好的可用性。

### 聊天窗口尺寸

聊天窗口在桌面上宽度为 410px，间距为 20px，并带有一个指向高亮文本的 16px 视觉箭头。这些尺寸是固定的以确保行为一致，但您可以使用 CSS 自定义外观。

### 跨元素选择

用户可以选择跨越多个 HTML 元素的文本，例如从一个段落的中间高亮到另一个段落的开头。范围序列化系统能够正确处理这种情况，即使跨越元素边界也会高亮所有选定的文本。

### 浏览器兼容性

文本选择系统使用标准的 `window.getSelection()` API，所有现代浏览器都支持该 API。对于较旧版本的 Internet Explorer，它会回退到 `document.selection` 以保持兼容性。

### 选择持久化

一旦为文本选择创建了会话，即使页面重新加载，该批注也会持续存在。序列化的范围和 DOM 路径使组件能够在用户返回页面时在完全相同的位置恢复高亮。

只要您的页面内容保持稳定，这就能可靠地工作。如果您更改了文本内容或重构了 HTML，现有批注可能无法再与文本正确对齐。因此，最好避免在带有活动批注的页面上进行重大内容更改，或者在必须更改内容时考虑迁移批注。
