FastComments는 SSO와 SAML 인증을 모두 제공합니다. 두 방식의 차이를 이해하면 조직에 맞는 올바른 접근 방식을 선택하는 데 도움이 됩니다.

### Simple/Secure SSO 소개

FastComments는 사이트를 통해 댓글 위젯에 인증하기 위한 두 가지 SSO 흐름을 제공합니다.
이는 SAML과 다르며 SAML을 필요로 하지 않습니다. 대신 Simple SSO는 댓글 위젯에 객체를 전달하기만 하면 되고,
Secure SSO는 여기에 더해 API 키로 페이로드를 해싱합니다.

반면 SAML은 사용자의 권한에 따라 댓글 위젯뿐만 아니라 *전체 제품*에 대해 사용자를 인증합니다
(사용자가 우리 도메인에 대해 타사 쿠키를 활성화한 경우).

### SAML 인증

SAML은 더 강력한 보안 및 통합 기능을 제공하는 엔터프라이즈급 인증 프로토콜입니다:

- **구현**: IdP(Identity Provider) 구성 및 인증서 교환이 필요합니다
- **보안**: 서명된 XML 어설션을 사용하며 암호화를 지원합니다
- **사용 사례**: 기존 SAML 인프라(Active Directory, Okta 등)를 보유한 기업에 이상적입니다
- **설정 복잡도**: 더 복잡합니다 - IdP 구성 및 인증서 관리가 필요합니다
- **엔터프라이즈 기능**: 고급 역할 매핑, 중앙 집중식 사용자 관리, 감사 추적

### SAML을 선택해야 하는 경우

다음과 같은 경우 SAML 인증을 고려하세요:

- 이미 SAML 호환 ID 공급자(Okta, Azure AD, ADFS 등)를 사용 중인 경우
- 엔터프라이즈급 보안 및 규정 준수가 필요한 경우
- 중앙 집중식 사용자 관리 및 액세스 제어가 필요한 경우
- SAML을 인증에 사용하는 여러 애플리케이션을 보유한 경우
- 상세한 감사 추적 및 보안 보고가 필요한 경우

### Simple 또는 Secure SSO를 선택해야 하는 경우

다음과 같은 경우 위젯 중심의 SSO 솔루션으로 충분할 수 있습니다:

- 자체 인증 시스템을 보유한 경우
- 최소한의 설정으로 빠른 구현이 필요한 경우
- 엔터프라이즈 ID 공급자 통합이 필요하지 않은 경우
- 애플리케이션에서 직접 사용자 데이터를 제어하고 싶은 경우
- 더 간단한 보안 요구 사항을 가진 경우

Simple 및 Secure SSO는 사용자가 *사이트나 앱을 통해* 이미 계정을 보유하고 있지만 반드시 SAML을 사용하지는 않는 온라인 포털, 블로그 등에서 일반적으로 사용됩니다.
