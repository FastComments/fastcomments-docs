जब FastComments में SAML सक्षम किया जाता है, तो सिस्टम स्वचालित रूप से Service Provider (SP) जानकारी जनरेट करता है जिसे आपको अपने identity provider में कॉन्फ़िगर करने की आवश्यकता होती है।

### Service Provider जानकारी तक पहुँचना

SAML प्रमाणीकरण सक्षम करने के बाद SP जानकारी आपके SAML कॉन्फ़िगरेशन पेज पर दिखाई जाती है। इस जानकारी में वे सभी विवरण शामिल हैं जिनकी आवश्यकता आपके identity provider को SAML ट्रस्ट संबंध स्थापित करने के लिए होती है।

### Service Provider Endpoints

#### SP Entity ID / Audience
**उद्देश्य**: आपके FastComments इंस्टेंस को service provider के रूप में विशिष्ट रूप से पहचानता है
**प्रारूप**: `https://fastcomments.com/saml/{your-tenant-id}`
**उपयोग**: इसे अपने IdP में Entity ID या Audience के रूप में कॉन्फ़िगर करें

यह पहचानकर्ता सुनिश्चित करता है कि SAML प्रतिक्रियाएँ आपके विशिष्ट FastComments टेनेंट के लिए हैं और SAML प्रतिक्रियाओं को अन्य इंस्टेंस द्वारा स्वीकार किए जाने से रोकता है।

#### Assertion Consumer Service (ACS) URL
**उद्देश्य**: वह endpoint जहाँ आपका IdP उपयोगकर्ता प्रमाणीकरण के बाद SAML प्रतिक्रियाएँ भेजता है
**प्रारूप**: `https://fastcomments.com/saml/callback/{your-tenant-id}`
**उपयोग**: इसे अपने IdP में ACS URL या Reply URL के रूप में कॉन्फ़िगर करें

यह वह जगह है जहाँ आपके identity provider के साथ सफल प्रमाणीकरण के बाद उपयोगकर्ताओं को, उपयोगकर्ता जानकारी युक्त SAML assertion के साथ, रीडायरेक्ट किया जाता है।

#### SP Metadata URL
**उद्देश्य**: मानक XML प्रारूप में पूर्ण SAML कॉन्फ़िगरेशन प्रदान करता है
**प्रारूप**: `https://fastcomments.com/saml/metadata/{your-tenant-id}`
**उपयोग**: कुछ IdPs इस URL का उपयोग करके कॉन्फ़िगरेशन को स्वचालित रूप से आयात कर सकते हैं

metadata URL में सभी आवश्यक SP जानकारी XML प्रारूप में होती है, जिससे संगत identity providers को स्वचालित रूप से कॉन्फ़िगर करना आसान हो जाता है।

#### SAML Login URL
**उद्देश्य**: आपके टेनेंट के लिए SAML प्रमाणीकरण शुरू करने का सीधा लिंक
**प्रारूप**: `https://fastcomments.com/saml/login/{your-tenant-id}`
**उपयोग**: उपयोगकर्ताओं को सीधे SAML प्रमाणीकरण से लिंक करें या फ़्लो का परीक्षण करें

आप इस URL का उपयोग SAML प्रमाणीकरण का परीक्षण करने या उपयोगकर्ताओं को SAML के माध्यम से साइन इन करने के लिए सीधा लिंक प्रदान करने के लिए कर सकते हैं।

### SAML बाइंडिंग समर्थन

FastComments निम्नलिखित SAML बाइंडिंग्स का समर्थन करता है:

#### HTTP-POST बाइंडिंग
- **प्राथमिक विधि**: SAML प्रतिक्रियाओं के लिए सबसे सामान्य बाइंडिंग
- **सुरक्षा**: SAML प्रतिक्रिया HTTP POST के माध्यम से ACS URL पर भेजी जाती है
- **उपयोग**: प्रोडक्शन डिप्लॉयमेंट के लिए अनुशंसित

#### HTTP-Redirect बाइंडिंग
- **वैकल्पिक विधि**: SAML प्रतिक्रिया HTTP रीडायरेक्ट के माध्यम से भेजी जाती है
- **सीमाएँ**: URL लंबाई प्रतिबंधों के कारण सीमित पेलोड आकार
- **उपयोग**: समर्थित है लेकिन HTTP-POST बेहतर है

### Name ID नीति

FastComments SAML अनुरोधों में निम्नलिखित Name ID नीति कॉन्फ़िगर करता है:

- **डिफ़ॉल्ट प्रारूप**: `urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress`
- **वैकल्पिक प्रारूप**: Persistent, Transient, Unspecified (कॉन्फ़िगर योग्य)
- **आवश्यकता**: ईमेल पता मुख्य उपयोगकर्ता पहचानकर्ता के रूप में उपयोग किया जाता है

### SAML अनुरोध विशेषताएँ

SAML प्रमाणीकरण शुरू करते समय, FastComments इन विशेषताओं के साथ अनुरोध भेजता है:

#### अनुरोध साइनिंग
- **स्थिति**: वैकल्पिक (कॉन्फ़िगर योग्य)
- **एल्गोरिथम**: कॉन्फ़िगर किए गए सिग्नेचर एल्गोरिथम से मेल खाता है
- **प्रमाणपत्र**: अनुरोध साइनिंग सक्षम होने पर टेनेंट-विशिष्ट प्रमाणपत्र का उपयोग करता है

#### अनुरोधित विशेषताएँ
FastComments SAML AuthnRequests में निम्नलिखित विशेषताओं का अनुरोध करता है:

- **Email**: उपयोगकर्ता पहचान के लिए आवश्यक
- **First Name**: प्रदर्शन उद्देश्यों के लिए वैकल्पिक
- **Last Name**: प्रदर्शन उद्देश्यों के लिए वैकल्पिक
- **Roles/Groups**: एक्सेस नियंत्रण और अनुमतियों के लिए वैकल्पिक

### SP जानकारी कॉपी करना

SAML कॉन्फ़िगरेशन पेज क्लिक करने योग्य फ़ील्ड प्रदान करता है जो स्वचालित रूप से SP जानकारी को आपके क्लिपबोर्ड पर कॉपी करते हैं:

1. किसी भी SP जानकारी फ़ील्ड पर क्लिक करें (Entity ID, ACS URL, आदि)
2. मान स्वचालित रूप से आपके क्लिपबोर्ड पर कॉपी हो जाता है
3. मान को अपने identity provider कॉन्फ़िगरेशन में पेस्ट करें
4. सफल कॉपी होने का संकेत एक संक्षिप्त हाइलाइट देता है

इससे SP जानकारी को बिना टाइपिंग त्रुटियों के आपके IdP में सटीक रूप से स्थानांतरित करना आसान हो जाता है।

### SP प्रमाणपत्र जानकारी

#### प्रमाणपत्र का उपयोग
- **उद्देश्य**: संचार को एन्क्रिप्ट करता है और SP पहचान सत्यापित करता है
- **रोटेशन**: प्रमाणपत्र स्वचालित रूप से FastComments द्वारा प्रबंधित होते हैं
- **एक्सेस**: सार्वजनिक प्रमाणपत्र metadata URL के माध्यम से उपलब्ध हैं

#### प्रमाणपत्र विवरण
- **एल्गोरिथम**: RSA-2048 या उच्चतर
- **वैधता**: प्रमाणपत्र समाप्ति से पहले स्वचालित रूप से नवीनीकृत हो जाते हैं
- **वितरण**: मानक SAML metadata के माध्यम से उपलब्ध

### SP कॉन्फ़िगरेशन की समस्या निवारण

यदि आपका identity provider SP जानकारी के साथ समस्याओं की रिपोर्ट करता है:

1. **URL सत्यापित करें**: सुनिश्चित करें कि सभी URLs HTTPS का उपयोग करते हैं और सही tenant ID शामिल करते हैं
2. **Metadata जाँचें**: कॉन्फ़िगरेशन सत्यापित करने के लिए metadata URL का उपयोग करें
3. **कनेक्टिविटी परीक्षण करें**: सुनिश्चित करें कि आपका IdP FastComments endpoints तक पहुँच सकता है
4. **प्रारूप सत्यापित करें**: पुष्टि करें कि आपका IdP SP जानकारी प्रारूप का समर्थन करता है

सामान्य समस्याओं में शामिल हैं:
- URLs में गलत tenant ID
- IdP और FastComments के बीच नेटवर्क कनेक्टिविटी समस्याएँ
- IdP द्वारा अलग URL प्रारूप या अतिरिक्त कॉन्फ़िगरेशन विकल्पों की अपेक्षा
