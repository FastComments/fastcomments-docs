כאשר SAML מופעל ב-FastComments, המערכת מייצרת באופן אוטומטי מידע של ספק שירות (SP) שעליך להגדיר בספק הזהויות שלך.

### גישה למידע של ספק השירות

מידע ה-SP מוצג בדף הגדרות ה-SAML שלך לאחר הפעלת אימות SAML. מידע זה כולל את כל הפרטים שספק הזהויות שלך צריך כדי ליצור את יחסי האמון של SAML.

### נקודות קצה של ספק השירות

#### SP Entity ID / Audience
**מטרה**: מזהה באופן ייחודי את המופע שלך ב-FastComments כספק שירות
**פורמט**: `https://fastcomments.com/saml/{your-tenant-id}`
**שימוש**: הגדר זאת כ-Entity ID או Audience ב-IdP שלך

מזהה זה מבטיח שתגובות SAML מיועדות לטננט הספציפי שלך ב-FastComments ומונע מתגובות SAML להתקבל על ידי מופעים אחרים.

#### Assertion Consumer Service (ACS) URL
**מטרה**: נקודת הקצה אליה ה-IdP שלך שולח תגובות SAML לאחר אימות המשתמש
**פורמט**: `https://fastcomments.com/saml/callback/{your-tenant-id}`
**שימוש**: הגדר זאת כ-ACS URL או Reply URL ב-IdP שלך

זהו המקום אליו משתמשים מועברים לאחר אימות מוצלח מול ספק הזהויות שלך, יחד עם הצהרת ה-SAML המכילה מידע על המשתמש.

#### SP Metadata URL
**מטרה**: מספק תצורת SAML מלאה בפורמט XML תקני
**פורמט**: `https://fastcomments.com/saml/metadata/{your-tenant-id}`
**שימוש**: חלק מה-IdPs יכולים לייבא תצורה באופן אוטומטי באמצעות כתובת URL זו

כתובת ה-metadata מכילה את כל מידע ה-SP הדרוש בפורמט XML, מה שמקל על הגדרת ספקי זהויות תואמים באופן אוטומטי.

#### SAML Login URL
**מטרה**: קישור ישיר ליזום אימות SAML עבור הטננט שלך
**פורמט**: `https://fastcomments.com/saml/login/{your-tenant-id}`
**שימוש**: קישור משתמשים ישירות לאימות SAML או בדיקת הזרימה

באפשרותך להשתמש בכתובת URL זו כדי לבדוק אימות SAML או לספק למשתמשים קישור ישיר להתחברות באמצעות SAML.

### תמיכה ב-SAML Bindings

FastComments תומך ב-SAML bindings הבאים:

#### HTTP-POST Binding
- **שיטה עיקרית**: ה-binding הנפוץ ביותר עבור תגובות SAML
- **אבטחה**: תגובת ה-SAML נשלחת באמצעות HTTP POST אל כתובת ה-ACS URL
- **שימוש**: מומלץ לפריסות בסביבת הייצור

#### HTTP-Redirect Binding
- **שיטה חלופית**: תגובת SAML נשלחת באמצעות הפניית HTTP
- **מגבלות**: גודל מטען מוגבל עקב מגבלות אורך URL
- **שימוש**: נתמך, אך HTTP-POST מועדף

### מדיניות Name ID

FastComments מגדיר את מדיניות ה-Name ID הבאה בבקשות SAML:

- **פורמט ברירת מחדל**: `urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress`
- **פורמטים חלופיים**: Persistent, Transient, Unspecified (ניתן להגדרה)
- **דרישה**: כתובת הדוא"ל משמשת כמזהה המשתמש הראשי

### מאפייני בקשות SAML

בעת יזום אימות SAML, FastComments שולח בקשות עם המאפיינים הבאים:

#### חתימת בקשות
- **סטטוס**: אופציונלי (ניתן להגדרה)
- **אלגוריתם**: תואם לאלגוריתם החתימה המוגדר
- **תעודה**: משתמש בתעודה ייחודית לטננט אם חתימת בקשות מופעלת

#### מאפיינים מבוקשים
FastComments מבקש את המאפיינים הבאים בבקשות SAML AuthnRequests:

- **Email**: נדרש לזיהוי המשתמש
- **First Name**: אופציונלי לצורכי תצוגה
- **Last Name**: אופציונלי לצורכי תצוגה
- **Roles/Groups**: אופציונלי לבקרת גישה והרשאות

### העתקת מידע SP

דף הגדרות ה-SAML מספק שדות לחיצים שמעתיקים באופן אוטומטי מידע SP ללוח שלך:

1. לחץ על כל שדה מידע SP (Entity ID, ACS URL וכו')
2. הערך מועתק באופן אוטומטי ללוח שלך
3. הדבק את הערך בתצורת ספק הזהויות שלך
4. הדגשה קצרה מציינת העתקה מוצלחת

זה מקל על העברת מידע ה-SP במדויק אל ה-IdP שלך ללא שגיאות הקלדה.

### מידע על תעודת SP

#### שימוש בתעודה
- **מטרה**: מצפין תקשורת ומאמת את זהות ה-SP
- **החלפה**: תעודות מנוהלות באופן אוטומטי על ידי FastComments
- **גישה**: תעודות ציבוריות זמינות באמצעות כתובת ה-metadata

#### פרטי התעודה
- **אלגוריתם**: RSA-2048 או גבוה יותר
- **תוקף**: תעודות מחודשות באופן אוטומטי לפני פקיעתן
- **הפצה**: זמינות באמצעות metadata תקני של SAML

### פתרון בעיות בתצורת SP

אם ספק הזהויות שלך מדווח על בעיות במידע ה-SP:

1. **אמת כתובות URL**: ודא שכל הכתובות משתמשות ב-HTTPS וכוללות את מזהה הטננט הנכון
2. **בדוק Metadata**: השתמש בכתובת ה-metadata כדי לאמת את התצורה
3. **בדוק קישוריות**: ודא שה-IdP שלך יכול להגיע לנקודות הקצה של FastComments
4. **אמת פורמט**: ודא שה-IdP שלך תומך בפורמט של מידע ה-SP

בעיות נפוצות כוללות:
- מזהה טננט שגוי בכתובות URL
- בעיות קישוריות רשת בין ה-IdP ל-FastComments
- IdP שמצפה לפורמטי URL שונים או לאפשרויות תצורה נוספות
