Το κλικ στο **View** σε μια γραμμή στο [Run History](#run-history) ανοίγει τη σελίδα λεπτομερειών εκτέλεσης. Εδώ διαβάζετε τη συλλογιστική του agent και κρίνετε τις αποφάσεις του.

### Επάνω μέρος: σύνοψη εκτέλεσης

- **Agent** - ποιος agent εκτέλεσε.
- **When** - χρονική σήμανση.
- **Status** - Started / Success / Error, συν το σήμα **Dry Run** αν ισχύει.
- **Cost** - κόστος ανά εκτέλεση στο νόμισμα του tenant σας.
- **Cost per action** - κόστος διαιρεμένο με τον αριθμό των μη εκκρεμών ενεργειών, χρήσιμο για τον εντοπισμό ασυνήθιστα ακριβών εκτελέσεων.

### Ενέργειες που έγιναν

Μια λίστα, με τη σειρά, κάθε κλήσης εργαλείου που έκανε η εκτέλεση. Κάθε καταχώρηση δείχνει:

- **Action label** - "Wrote a comment", "Marked a comment as spam", "Banned a user" και ούτω καθεξής. Η ετικέτα αντιστοιχίζεται από το enum του τύπου ενέργειας.
- **Reference ID** - το επηρεασμένο σχόλιο, χρήστη ή badge ID, που εμφανίζεται ως κείμενο μονοδιάστατης γραμματοσειράς (όχι υπερσύνδεσμος).
- **Agent reasoning** - η αιτιολόγηση που παρείχε ο agent μαζί με την κλήση.
- **Confidence** - η αυτοαξιολογούμενη βεβαιότητα του agent, που εμφανίζεται ως ποσοστό.
- Σήμα **Pending approval** - αν η ενέργεια βρίσκεται σε αναμονή στο [approvals inbox](#approval-workflow) αντί να έχει εκτελεστεί.

Αν η εκτέλεση δεν έκανε καμία ενέργεια, η ενότητα γράφει: "No actions were taken during this run."

### LLM transcript

Κάτω από τις ενέργειες, το πλήρες απομαγνητοφώνημα της συνομιλίας του agent με το LLM:

- **System** - το system prompt (επίθημα πλατφόρμας + το αρχικό σας prompt + οδηγίες κοινότητας).
- **User** - το μήνυμα περιεχομένου που περιγράφει το έναυσμα.
- **Assistant** - οι απαντήσεις του μοντέλου, συμπεριλαμβανομένων των κλήσεων εργαλείων.
- **Tool** - το αποτέλεσμα του εργαλείου που τροφοδοτήθηκε πίσω στο μοντέλο (π.χ., τι επέστρεψε το `search_memory`).

Τα μεγάλα μηνύματα είναι αναδιπλούμενα· κάντε κλικ στο **Expand** / **Collapse** για προβολή.

### Ανάγνωση απομαγνητοφωνημάτων

Το απομαγνητοφώνημα είναι η πιο σημαντική σελίδα για τη βελτίωση. Όταν ο agent παίρνει μια απόφαση με την οποία διαφωνείτε, διαβάστε το ξανά για να δείτε:

- Τι **είδε** το μοντέλο (το μήνυμα περιεχομένου User).
- Τι **αποφάσισε** το μοντέλο (τις κλήσεις εργαλείων Assistant).
- Τι **εξέτασε** το μοντέλο (οποιαδήποτε αποτελέσματα εργαλείων - π.χ., αν ο agent όντως κάλεσε το `search_memory` και αν βρήκε κάτι πριν κάνει ban).

Αν το μοντέλο κάνει σταθερά το ίδιο είδος λάθους, επεξεργαστείτε το [initial prompt](#personality-prompt) - ή χρησιμοποιήστε το [Refining Prompts](#refining-prompts) από μια απορριφθείσα έγκριση.

### Αναφορές ενεργειών

Τα reference IDs εμφανίζονται ως κείμενο μονοδιάστατης γραμματοσειράς (όχι υπερσυνδέσμοι):

- Σχόλια: το comment ID.
- Χρήστες: το user ID.
- Badges: το badge ID.

Μπορείτε να αντιγράψετε το ID για να αναζητήσετε την επηρεασμένη εγγραφή στη σχετική σελίδα moderation/admin.

### Τι λείπει στο dry-run

Οι εκτελέσεις dry-run δείχνουν τις **ίδιες** ενέργειες, αιτιολογήσεις και βαθμολογίες βεβαιότητας. Η μόνη διαφορά είναι το σήμα **Dry Run** στη γραμμή κατάστασης. Τα reference IDs για σχόλια / χρήστες / badges εξακολουθούν να εμφανίζονται - ο agent απλώς δεν τα επηρέασε.

### Σφάλματα

Για εκτελέσεις σε κατάσταση `Error`, η σελίδα λεπτομερειών δείχνει το υποκείμενο μήνυμα σφάλματος. Συνηθισμένα σφάλματα:

- **No LLM API key configured** - λανθασμένη ρύθμιση tenant ή πλατφόρμας.
- **LLM call timeout** - ο πάροχος LLM ήταν αργός ή μη διαθέσιμος.
- **Tool dispatch failure** - ο agent επέλεξε ένα εργαλείο με λάθος ορίσματα (π.χ., ένα comment ID που δεν υπάρχει πλέον).
- **Budget exhausted mid-run** - το όριο του agent εξαντλήθηκε ενώ η εκτέλεση ήταν σε εξέλιξη. Η εκτέλεση διακόπηκε.

Τα σφάλματα δεν αναιρούν μερικές ενέργειες - τυχόν κλήσεις εργαλείων που ολοκληρώθηκαν πριν το σφάλμα παραμένουν.
