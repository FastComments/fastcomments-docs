Ένας agent έχει μία από τρεις καταστάσεις:

### Disabled

Ο agent είναι απενεργοποιημένος. Δεν επεξεργάζονται triggers και ο agent δεν εμφανίζεται στη διαδρομή αποστολής. Το ιστορικό εκτελέσεων, τα analytics και η μνήμη του παραμένουν - αν τον ενεργοποιήσετε ξανά αργότερα, τα ιστορικά δεδομένα είναι ακόμα εκεί.

Χρησιμοποιήστε `Disabled` όταν:
- Θέλετε να βγάλετε έναν agent εκτός λειτουργίας χωρίς να τον χάσετε.
- Ένας agent συμπεριφέρεται προβληματικά και πρέπει να τον σταματήσετε αμέσως ενώ διερευνάτε.
- Εναλλάσσετε εποχιακά agents (π.χ. έναν χαιρετισμό μόνο για τις γιορτές).

### Dry Run - προεπιλογή για νέους agents

Ο agent εκτελείται από άκρη σε άκρη - επεξεργάζεται triggers, καλεί το LLM, επιλέγει κλήσεις εργαλείων, υπολογίζει αιτιολογήσεις και βαθμό εμπιστοσύνης - αλλά **δεν εκτελείται καμία πραγματική ενέργεια**. Κάθε εκτέλεση καταγράφεται με το σήμα **Dry Run** στο [Run History](#run-history).

Χρησιμοποιήστε `Dry Run` όταν:
- Ένας νέος agent μόλις δημιουργήθηκε. Κάθε starter template ξεκινά σε dry-run.
- Έχετε επεξεργαστεί το prompt ή αλλάξει το σύνολο των triggers και θέλετε να δείτε πώς θα εξελιχθεί η αλλαγή πριν την οριστικοποιήσετε.
- Εκτελείτε μια [δοκιμαστική εκτέλεση / replay](#test-runs-replays) (τα replays επιβάλλουν dry-run ανεξάρτητα από την κατάσταση του agent).

Η πλατφόρμα χρεώνει tokens για εκτελέσεις dry-run - η κλήση LLM εξακολουθεί να γίνεται, μόνο οι παρενέργειες παραλείπονται. Τα όρια προϋπολογισμού ισχύουν και για το dry-run. Δείτε [Budgets Overview](#budgets-overview).

### Enabled

Ο agent εκτελεί πραγματικές ενέργειες. Οι κλήσεις εργαλείων εκτελούνται - ή μπαίνουν σε ουρά για [έγκριση](#approval-workflow) αν η ενέργεια απαιτεί έγκριση.

Χρησιμοποιήστε `Enabled` αφού η έξοδος του dry-run φαίνεται σωστή.

### Αλλαγή κατάστασης

Μπορείτε να εναλλάσσετε οποιεσδήποτε δύο καταστάσεις στη φόρμα επεξεργασίας. Η μετάβαση από Dry Run σε Enabled δεν εκτελεί αναδρομικά ξανά τις ενέργειες του dry-run - αυτές παραμένουν ως ιστορικό dry-run. Τα νέα triggers από εκείνη τη στιγμή και μετά εκτελούνται σε πραγματικές συνθήκες.

Η μετάβαση από Enabled σε Disabled κατά τη διάρκεια εκτέλεσης **δεν** διακόπτει μια εκτέλεση σε εξέλιξη. Το trigger που εκτελείται αυτή τη στιγμή ολοκληρώνεται (με ό,τι έχει ήδη ξεκινήσει)· το επόμενο trigger απορρίπτεται επειδή ο agent είναι πλέον Disabled.

### Κατάσταση κατά προβλήματα χρέωσης

Αν η χρέωση του tenant σας καταστεί άκυρη, όλοι οι agents τελικά τεθούν σε παύση ανεξάρτητα από την αποθηκευμένη κατάσταση - τα triggers απορρίπτονται με `BILLING_INVALID` μέχρι να αποκατασταθεί η χρέωση. Το αποθηκευμένο πεδίο κατάστασης δεν αλλάζει· ο dispatcher απλώς αρνείται να εκτελέσει. Δείτε [Plans and Eligibility](#plans-and-eligibility).
