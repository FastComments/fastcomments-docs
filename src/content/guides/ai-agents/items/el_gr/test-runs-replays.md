Μια **δοκιμαστική εκτέλεση** (test run, λέγεται και **replay**) εκτελεί τον agent σε ένα παράθυρο ιστορικών σχολίων **χωρίς να πραγματοποιεί πραγματικές ενέργειες**. Είναι ο ταχύτερος τρόπος προεπισκόπησης της συμπεριφοράς του agent πριν βγει σε παραγωγή.

Είναι προσβάσιμη από τη σελίδα λίστας agents μέσω του κουμπιού **Test run** στη γραμμή κάθε agent.

### Τι κάνει

Η πλατφόρμα:

1. Επιλέγει ένα δείγμα ιστορικών σχολίων που ταιριάζουν με το πεδίο εφαρμογής του agent, στο παράθυρο που επιλέγετε.
2. Για κάθε σχόλιο, εκτελεί τον agent από άκρη σε άκρη σαν το σχόλιο να είχε δημοσιευτεί μόλις τώρα - ίδιο context, ίδια κλήση LLM, ίδια επιλογή εργαλείων, ίδιες αιτιολογήσεις και βαθμοί εμπιστοσύνης.
3. Καταγράφει κάθε εκτέλεση ως dry-run, με ετικέτα ώστε να παραμένει ομαδοποιημένη με το replay από το οποίο προήλθε και να εξαιρείται από τις προβολές ζωντανών εκτελέσεων.
4. **Συγκρίνει** την κρίση του agent με το τι πραγματικά συνέβη στο σχόλιο - εγκρίθηκε αργότερα, επισημάνθηκε ως spam, διαγράφηκε, μπλοκαρίστηκε από τη μηχανή spam κ.ο.κ.

Το αποτέλεσμα είναι μια διαφορά ανά σχόλιο: «Το replay agent θα το σημαίανε ως spam, αλλά το σχόλιο είναι προς το παρόν εγκεκριμένο και καθαρό.»

### Ρυθμίσεις

Η σελίδα δοκιμαστικής εκτέλεσης έχει μία μόνο είσοδο:

- **Ημέρες ιστορικών σχολίων προς αξιολόγηση** - ένας αριθμητικός πεδίο `days` μεταξύ 1 και 90. Παλαιότερα σχόλια δεν είναι επιλέξιμα.

Το μέγεθος δείγματος και το σκληρό όριο **δεν εκτίθενται στο UI** - και τα δύο είναι προεπιλεγμένες τιμές διακομιστή ανά plan. Η σελίδα εμφανίζει ενημερωτικά πεδία:

- **Σχόλια που ταιριάζουν στο παράθυρο** - πόσα σχόλια θα ληφθούν υπόψη.
- **Έως N σχόλια από αυτό το παράθυρο θα επεξεργαστούν** - το αποτελεσματικό μέγεθος δείγματος βάσει του ορίου του διακομιστή.
- **Εκτιμώμενο κόστος** - στο νόμισμα του tenant σας.

### Όριο ρυθμού

Κάθε χρήστης περιορίζεται σε **10 δοκιμαστικές εκτελέσεις ανά 24 ώρες** (με rate limit μέσω του κλειδιού `replay-create:${requestedBy}`). Το κουμπί εμφανίζει tooltip όταν έχετε φτάσει το όριο («Έχετε φτάσει τις 10 δοκιμαστικές εκτελέσεις στις τελευταίες 24 ώρες.»).

### Ταυτόχρονη εκτέλεση

Μόνο ένα replay μπορεί να είναι ενεργό ανά agent κάθε φορά. Αν ξεκινήσετε δεύτερο replay ενώ ένα βρίσκεται σε εξέλιξη, ανακατευθύνεστε σε αυτό που είναι σε εξέλιξη.

### Ανάγνωση αποτελεσμάτων

Όταν το replay ολοκληρωθεί, η σελίδα αποτελεσμάτων εμφανίζει tabs:

- **Deltas** (ενεργό από προεπιλογή) - η κρίση του replay agent διαφέρει από την πραγματικότητα. (Το πιο ενδιαφέρον - «ο agent θα το σημαίανε ως spam, αλλά το σχόλιο εγκρίθηκε και είναι εντάξει».)
- **Matches** - η κρίση του replay agent ταιριάζει με το τι πραγματικά συνέβη. (Καθησυχαστικό - ο agent συμφωνεί με την πραγματικότητα.)
- **No action** - το replay agent αποφάσισε να μην κάνει τίποτα. (Μερικές φορές είναι η σωστή απάντηση· μερικές φορές ο agent έχασε κάτι.)
- **All** - κάθε αποτέλεσμα ανεξαρτήτως ταξινόμησης.

Για κάθε σχόλιο σε οποιοδήποτε tab:

- **Προηγούμενο αποτέλεσμα** - η ταξινόμηση του τι πραγματικά συνέβη: **POSITIVE**, **NEGATIVE** ή **INDETERMINATE**, με **Evidence** («Το σχόλιο επισημάνθηκε ως διαγραμμένο στις {date}», «Engine: bayes» κ.ο.κ.).
- **Το replay agent θα** - η ενέργεια που επέλεξε ο agent.
- **Γιατί** - η αιτιολόγηση.
- **Εμπιστοσύνη** - εμφανίζεται ως ποσοστό.

### Γιατί τα replay επιβάλλουν dry-run

Ένα replay σε ένα σχόλιο που διαγράφηκε πριν από τέσσερις μήνες δεν θα πρέπει να το διαγράψει αναδρομικά - είναι ήδη διαγραμμένο. Ένα replay σε ένα σχόλιο που ο agent τώρα θέλει να εγκρίνει δεν θα πρέπει να αλλάξει την τρέχουσα κατάσταση του σχολίου. Το replay είναι εργαλείο προεπισκόπησης. Η επιβολή dry-run είναι αυτό που κάνει ασφαλές να εκτελεστεί ένα replay σε οποιοδήποτε παράθυρο ιστορικού.

### Αναπαραγωγιμότητα

Τα replay παγώνουν τη ρύθμιση του agent τη στιγμή που ξεκίνησε το replay. Μεταγενέστερες αλλαγές στον agent δεν αλλάζουν τα αποτελέσματα του replay - η σελίδα αποτελεσμάτων παραμένει σταθερή ως καταγραφή του τι θα είχε κάνει *αυτή* η έκδοση του agent.

### Πότε τα budgets σταματούν ένα replay

Τα replay υπόκεινται σε:

- Το δικό τους **σκληρό όριο** (ορίζεται στη φόρμα replay).
- Τα ημερήσια και μηνιαία **όρια budget** του agent.
- Τα ημερήσια και μηνιαία **όρια budget** του tenant.

Το πρώτο όριο που επιτυγχάνεται διακόπτει το replay με συγκεκριμένο κωδικό σφάλματος. Τυχόν αποτελέσματα ανά σχόλιο που παράχθηκαν πριν τη διακοπή διατηρούνται στο [Run History](#run-history).

### Πώς εκτελούνται τα replay

Τα replay εκτελούνται στο παρασκήνιο, όχι συγχρόνως. Αφού κάνετε κλικ στο «Start test run», το replay μπαίνει σε ουρά και ένα worker το αναλαμβάνει. Ένα μεγάλο replay μπορεί να διαρκέσει αρκετά λεπτά. Η σελίδα αποτελεσμάτων κάνει polling και εμφανίζει πρόοδο (πλήθος επεξεργασμένων, δαπάνη μέχρι τώρα) καθώς προχωρά.

Αν ένα worker πεθάνει στη μέση ενός replay, η πλατφόρμα το επανατοποθετεί αυτόματα στην ουρά ώστε να συνεχίσει στο επόμενο πέρασμα. Ένα σύντομο κόλλημα δεν αφήνει ποτέ ένα replay ορφανό.

### Τι δεν κάνει το replay

- **Δεν τηρεί [καθυστερήσεις trigger](#trigger-deferred-delay).** Τα replay εκτελούνται αμέσως, όχι 30 λεπτά αργότερα.
- **Δεν γράφει στη μνήμη.** Τα replay agents δεν αποθηκεύουν σημειώσεις μνήμης, ακόμα κι αν η λογική τους κανονικά θα το έκανε.
- **Δεν ενεργοποιεί webhooks.** Τα triggers που παράγονται από replay δεν δημιουργούν γεγονότα webhook `trigger.succeeded` / `trigger.failed`.
- **Δεν εξαιρεί σχόλια που έχουν ήδη replay.** Η εκτέλεση δεύτερου replay στο ίδιο παράθυρο καλύπτει τα ίδια σχόλια.
