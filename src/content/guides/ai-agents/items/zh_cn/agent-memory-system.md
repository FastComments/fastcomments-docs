代理记忆（Agent memory）是一个按租户隔离的、**共享**的键值池，租户中的每个代理都可以从中读取和写入。它的存在是为了让代理能够在多次运行之间携带上下文。

### 为什么需要记忆

LLM 的上下文是按运行计算的。如果没有记忆，一个向用户发出警告的代理在下一次遇到同一用户时，无法得知之前的警告。平台的升级策略——“先警告后封禁”——依赖于代理能够找到之前的警告记录。记忆正是实现这一点的关键。

### 两种记忆类型

- **WARNING** - 作为 [`warn_user`](#tool-warn-user) 流程的一部分自动写入。代理不会手动写入 `WARNING` 记录；它们是警告用户的副作用。
- **NOTE** - 由 [`save_memory`](#tools-overview) 写入。是代理希望未来的代理了解的通用上下文。

升级策略在判断封禁是否合理时，会专门查找 `WARNING` 记录。

### 租户隔离，代理共享

租户中的所有代理共享**同一个记忆池**。代理 A 保存的备注对代理 B 的 `search_memory` 调用可见。这是有意为之的——你希望分诊代理的备注能为审核代理的决策提供参考。

`tenantId` 由执行器根据代理自身的租户设置——绝不来自 LLM 参数——因此从结构上杜绝了跨租户的记忆泄漏。

### 记忆记录的内容

每条记忆条目包含：

- **写入它的代理**，以及写入时间。
- **关于谁** - 该记忆所描述的用户。代理无法伪造这一点；平台会根据触发代理的事件自动填充。
- **隐藏的小号信号** - 平台还会（私下）记录原始评论的 IP 指纹，以便未来的记忆搜索能够显示关于从同一 IP 发帖的其他账户的备注。该指纹永远不会展示给代理或 LLM。
- **备注本身** - 最多 2000 个字符的自由文本。
- **用于检索的标签** - 最多 10 个短标签。
- **类型** - 警告或通用备注。
- **可选的评论链接** - 如果该记忆与某条特定评论相关联。

### 搜索行为

[`search_memory`](#tools-overview) 最多返回 25 条记录，按最新优先排序，范围自动限定为（触发用户的记录）或（与触发用户 IP 相同的其他账户的记录）。结果还有字符上限：所有返回内容的总字符数上限为 8000——如果达到上限，较旧的条目将被丢弃。

代理不会传递 `userId` 或 `targetIpHash`。两者都由执行器设置。

### 持久化

记忆**没有 TTL**。记录会一直保留，直到被显式删除。关于某用户的 WARNING 记录被有意设计为永不自动删除——升级历史必须能够无限期地被查到，否则平台“封禁前先搜索”的检查就毫无意义。

记忆被删除的三种方式：

- 审核员删除了底层评论 - 与该评论关联的所有记忆会被级联删除。
- 用户被删除 - 关于该用户的所有记忆条目会在同一事务中被删除。
- 你的租户被删除。

目前没有用于删除单条记忆记录的管理界面。

### 试运行中的记忆

试运行（dry-run）代理**不会**写入记忆。这是有意设计的：试运行代理的假设性决策不应污染共享记忆池。通过 `search_memory` 的读取在试运行中正常工作——代理可以看到来自正式代理的真实记忆——只是不能向其中添加内容。

### 回放中的记忆

与试运行相同：回放代理不写入记忆。回放仅用于预览。参见 [Test Runs (Replays)](#test-runs-replays)。

### 约束摘要

| 限制 | 值 |
|---|---|
| 记忆内容最大长度 | 2000 字符 |
| 记忆标签最大长度 | 64 字符 |
| 记忆标签最大数量 | 10 |
| 记忆查询最大长度 | 200 字符 |
| 记忆搜索结果上限 | 25 条记录 |
| 记忆搜索内容总量上限 | 8000 字符 |
