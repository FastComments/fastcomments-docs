**ドライラン(Dry Run)** は、すべての新しいエージェントが最初に起動される安全モードです。エージェントは、コミュニティに実際に作用する部分以外を、エンドツーエンドで実行します。

### ドライランで実行されること

- トリガーは通常どおり発火します。
- エージェントのプロンプト、[コミュニティガイドライン](#community-guidelines)、[コンテキスト](#context-options) が組み立てられます。
- LLM が呼び出されます。
- モデルがツール呼び出しを選択し、根拠と信頼度スコアを提供します。
- 実行は **ドライラン** バッジ付きで記録され、本番実行と明確に区別されます。

### ドライランで実行されないこと

- コメントの投稿、投票、コメントのピン留め/ピン留め解除/ロック/ロック解除は行われません。
- コメントのスパム判定、承認、レビューは行われません。
- ユーザーの BAN、警告、バッジ付与は行われません。
- メールは送信されません。
- メモリには書き込みが行われません。(そう、メモリも含まれます。ドライランのエージェントは、仮の判断によって共有メモリプールを汚染することができません。)
- ツールアクションに対する Webhook は発火しません。(トリガーレベルの `trigger.succeeded` / `trigger.failed` Webhook は引き続き発火し、ペイロードには `wasDryRun: true` が含まれます。[Webhook ペイロード](#webhook-payloads) を参照してください。)

### コスト

ドライランは、有効化された実行と **同じ LLM 呼び出し** を行います。トークンは課金され、[予算上限](#budgets-overview) が適用され、実行回数はエージェントごとおよびテナントごとの日次/月次制限にカウントされます。

このコストは、忠実なプレビューを得るための対価です。「LLM 呼び出しをスキップする」モードでは、エージェントがどのように振る舞うかについてのシグナルを一切得ることができません。

### ドライランの結果の読み方

[実行履歴](#run-history) では、ドライランの実行はステータス列に **ドライラン** バッジ付きで表示されます。各実行内のアクションは、本番アクションと同一に見えます - 同じツール名、同じ引数、同じ根拠と信頼度 - ただし、そのいずれも実際には行われていません。

[アナリティクスページ](#analytics-page) では、月ごとの「ドライラン vs 本番」の実行数が内訳表示され、トークン消費のどれだけが観察に使われたかを確認できます。

### ドライランからの切り替え

エージェントを編集し、**ステータス** を **有効** に変更します。次のトリガーから本番実行されます。

逆方向の切り替えも可能です - 有効からドライランへ - エージェントが望ましくない動作を始めた場合でも、ペナルティはありません。

### リプレイは強制的にドライランになる

[テスト実行(リプレイ)](#test-runs-replays) 機能は、エージェントの保存されたステータスに関係なく、過去のコメントに対してエージェントを **常にドライランで** 実行します。リプレイは過去のコメントに対して実際のアクションを実行できません。これは意図的な設計です - リプレイはプレビューツールであり、モデレーションツールではありません。
