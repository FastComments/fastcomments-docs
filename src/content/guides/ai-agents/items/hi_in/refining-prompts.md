**Refine Prompt** वह वर्कफ़्लो है जिसके द्वारा उन विशिष्ट निर्णयों के जवाब में, जिनसे आप असहमत हैं, एजेंट का [initial prompt](#personality-prompt) संपादित किया जाता है। इसे [approvals inbox](#approval-workflow) से लॉन्च किया जाता है।

### इसे कब उपयोग करें

जब आप खुद को बार-बार एक ही तरह की अप्रूवल reject करते हुए पाएं - "एजेंट लगातार बिना टारगेट के कठोर भाषा का उपयोग करने वाले लोगों को ban करना चाहता है" - तो इसे ठीक करने का उपाय एजेंट का prompt है। Refine Prompt एक निर्देशित तरीका है:

1. एक ऐसी विशिष्ट अप्रूवल चुनें जो गलत निर्णय का प्रतिनिधित्व करती हो।
2. इस बात के पूरे संदर्भ के साथ prompt संपादित करें कि एजेंट ने क्या किया और क्यों।
3. नया prompt एजेंट में सेव करें।

परिणाम एक ऐसा एजेंट होता है जो आगे चलकर वैसा ही निर्णय लेने की संभावना नहीं रखता।

### फ़्लो लॉन्च करना

`/auth/my-account/ai-agent-approvals` पर स्थित approvals inbox से:

1. एक **rejected** अप्रूवल खोलें। यह route REJECTED के अलावा किसी अन्य चीज़ को hard-reject करता है - pending और execution-failed अप्रूवल पात्र नहीं होते।
2. **Refine prompt** पर क्लिक करें।

आप `/auth/my-account/ai-agent-approvals/:approvalId/refine-prompt` पर prompt-refine UI पर पहुंच जाएंगे।

### पेज क्या दिखाता है

- **The approval** - reject किए गए निर्णय के लिए एजेंट का `toolName` और `justification` (पूरी LLM transcript यहां नहीं दिखाई जाती)।
- **The current prompt** - एजेंट का सेव किया गया [initial prompt](#personality-prompt)।
- **A feedback input** - आप **feedback** टाइप करते हैं जो बताता है कि क्या बदलना चाहिए (अधिकतम 2000 वर्ण)। फिर LLM आपके feedback से प्रस्तावित नया prompt जनरेट करता है।
- **Unified inline diff** - वर्तमान और प्रस्तावित prompt के बीच एक single inline diff (हटाए गए के लिए लाल, जोड़े गए के लिए हरा)।

संपादन करते समय अप्रूवल का संदर्भ ऊपर pinned रहता है ताकि आप "जिस केस को ठीक कर रहा हूं" का लगातार संदर्भ ले सकें।

### सेव करना

सेव करने पर एजेंट का `initialPrompt` फ़ील्ड अपडेट होता है। पिछले रन (और पिछली अप्रूवल) पुराने समय में दोबारा नहीं चलाए जाते - नया prompt केवल भविष्य के triggers को प्रभावित करता है। यदि आप सत्यापित करना चाहते हैं कि नया prompt समस्या ठीक करता है, तो पिछले 7 दिनों के विरुद्ध [test run / replay](#test-runs-replays) चलाएं और देखें कि क्या नया prompt अब भी reject की गई अप्रूवल उत्पन्न करता।

### यह फ़्लो क्या नहीं करता

- यह **community guidelines** संपादित नहीं करता - उस फ़ील्ड का अपना संपादक मुख्य एजेंट edit फ़ॉर्म पर है।
- यह **triggers**, **allowed tools**, या **approval gating** संपादित नहीं करता - वे मुख्य edit फ़ॉर्म पर ही रहते हैं।
- यह rollback के साथ prompt का versioning नहीं करता। पिछला prompt किसी अलग history collection में संग्रहित नहीं होता। यदि आपको rollback करना है, तो संपादन से पहले वर्तमान prompt को अपने tracking system में कॉपी कर लें।

### Refine को replay के साथ क्यों जोड़ें

परिणाम का परीक्षण किए बिना prompt संपादित करना विश्वास-आधारित है। अनुशंसित चक्र:

1. एक अप्रूवल reject करें।
2. Prompt refine करें।
3. पिछले 7 दिनों के विरुद्ध [test run](#test-runs-replays) चलाएं।
4. **Deltas** टैब देखें। क्या नए prompt ने गलत निर्णय को "would do" से हटाकर "would not do" में डाल दिया? क्या इसने गलती से अच्छे निर्णयों को भी बाहर कर दिया?
5. दोहराएं।

Refine + replay के तीन-चार चक्र आमतौर पर moderation एजेंट के लिए एक स्थिर prompt प्राप्त करने के लिए पर्याप्त होते हैं।

### Direct edit का विकल्प

आपको Refine Prompt का उपयोग करना ज़रूरी नहीं है - आप मुख्य edit फ़ॉर्म पर एजेंट को सीधे संपादित भी कर सकते हैं। Refine Prompt का एकमात्र लाभ यह है कि यह एक विशिष्ट विफल केस को pinned रखता है ताकि आपको यह न भूले कि आप किस चीज़ को ठीक कर रहे हैं।
