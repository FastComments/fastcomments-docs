---
Вебхуки агентов — это HTTP‑обратные вызовы, которые платформа отправляет, когда выполнение агента завершается или состояние одобрения изменяется. Используйте их, чтобы перенаправлять активность агентов в свои системы — панели модерации, журналы аудита, каналы Slack, инструменты эскалации.

Настраиваются на вкладке **Webhooks** на странице [AI Agents](https://fastcomments.com/auth/my-account/ai-agents)).

### Что доставляется

Четыре типа событий:

- **`trigger.succeeded`** — выполнение агента завершилось успешно.  
- **`trigger.failed`** — выполнение агента завершилось с ошибкой.  
- **`approval.requested`** — действие поставлено в очередь на одобрение человеком.  
- **`approval.decided`** — одобрение было одобрено, отклонено или выполнение завершилось с ошибкой.

Смотрите [Webhook Events](#webhook-events), чтобы узнать, какие события когда срабатывают, и [Webhook Payloads](#webhook-payloads) — схему каждого из них.

### Что не доставляется

- **Вебхуки для отдельных действий инструмента.** Запуск, который вызывает `pin_comment`, не генерирует отдельный вебхук для закрепления — действие включено в полезную нагрузку `trigger.succeeded` этого запуска. Если вам нужна доставка по каждому действию, разбирайте массив `actions` в полезной нагрузке триггера.  
- **Отброшенные триггеры.** Триггер, который не был отправлен (превышен бюджет, неверный контекст), не генерирует вебхук. Отбросы видны только на [странице аналитики](#analytics-page).  
- **Триггеры, созданные воспроизведением.** Тестовые запуски не генерируют вебхуки. См. [Test Runs (Replays)](#test-runs-replays).

### Конфигурация

Для каждого вебхука указываете:

- **URL** — HTTPS‑конечная точка, куда будет отправлен POST.  
- **Domain** — домен комментариев, к которому применяется вебхук (у вашего арендатора может быть несколько доменов). `*` — совпадение со всеми доменами; `*.example.com` — шаблон; точный домен — совпадение только с этим доменом.  
- **Events** — какие из четырёх типов событий подписать.  
- **Agents** — пусто — «все агенты», либо список конкретных идентификаторов агентов для фильтрации.  
- **Method** — POST или PUT (по умолчанию POST).  
- **No-retry status codes** — коды HTTP‑ответов, которые следует считать окончательными ошибками и не повторять (например, 410 Gone, 422 Unprocessable). См. [Webhook Retries](#webhook-retries).

Несколько вебхуков могут подписываться на одно и то же событие — каждый из них ставится в очередь независимо и доставляется на свой URL.

### Сопоставление по домену

Данное событие доставляется **каждому вебхуку, у которого поле `domain` совпадает с доменом комментария**. Сопоставление использует простой шаблон:

- Точный: `example.com` — совпадает только с `example.com`.  
- Подстановочный символ: `*` — совпадает со всеми доменами.  
- Шаблон поддомена: `*.example.com` — совпадает с `blog.example.com`, `forum.example.com`, но не с самим `example.com`.

Домен в полезной нагрузке берётся из первого ненулевого результата: домен комментария, URL, разобранный согласно конфигурации доменов арендатора, или поиск `Page` по `urlId`.

### Фильтрация по агенту

Поле **Agents** позволяет вебхуку подписаться только на определённые агенты. Пустое значение — «все агенты». Если указаны агенты, вебхук срабатывает только для них.

Это удобно, когда у вас есть один вебхук для событий модерации и другой для событий вовлечения, каждый из которых направляется в разные downstream‑системы.

### Тестовая отправка

В интерфейсе настройки вебхука есть кнопка **Test send**, которая отправляет фиктивную полезную нагрузку на указанный URL, чтобы вы могли проверить соединение, подпись и код ответа вашего эндпоинта без ожидания реального события.

### Журналы доставки

Каждая доставка (и каждая повторная попытка) попадает на страницу [Webhook Delivery Logs](#webhook-logs), где можно увидеть, что произошло «в проводе».

### Подпись

Каждый вебхук подписывается HMAC‑SHA256 с использованием API‑секрета вашего арендатора. См. [Webhook Signing](#webhook-signing).

### Право на использование

Вебхуки агентов требуют действующей оплаты арендатора. Они используют ту же инфраструктуру подписи/секрета, что и существующие вебхуки комментариев — если вы уже интегрировали вебхуки комментариев (см. [Webhooks guide](/guide-webhooks.html)), интеграция вебхуков агентов имеет ту же форму, но с новыми типами событий.
