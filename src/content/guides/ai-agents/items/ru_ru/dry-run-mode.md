**Пробный запуск (Dry Run)** — это безопасный режим, в котором начинает работу каждый новый агент. Агент выполняется от начала до конца, за исключением той части, где он взаимодействует с вашим сообществом.

### Что выполняется в режиме Dry Run

- Триггеры срабатывают как обычно.
- Промпт агента, [правила сообщества](#community-guidelines) и [контекст](#context-options) собираются вместе.
- Вызывается LLM.
- Модель выбирает вызовы инструментов и предоставляет обоснования + оценки уверенности.
- Запуск записывается с меткой **Dry Run**, чтобы его можно было чётко отличить от рабочих запусков.

### Что не выполняется в режиме Dry Run

- Комментарий не публикуется, голос не подаётся, комментарий не закрепляется/не открепляется/не блокируется/не разблокируется.
- Комментарий не помечается как спам, не одобряется и не проверяется.
- Пользователь не блокируется, не получает предупреждение и не награждается значком.
- Письма не отправляются.
- Память не записывается. (Да — включая память. Агенты в режиме Dry Run не могут «отравить» общий пул памяти гипотетическими решениями.)
- Вебхуки для действий инструментов не срабатывают. (Вебхуки уровня триггера `trigger.succeeded` / `trigger.failed` по-прежнему срабатывают, а полезная нагрузка включает `wasDryRun: true`. См. [Полезные нагрузки вебхуков](#webhook-payloads).)

### Сколько это стоит

Dry Run выполняет **тот же вызов LLM**, который выполнял бы рабочий запуск. Токены списываются, применяются [лимиты бюджета](#budgets-overview), а запуски учитываются в дневных/месячных лимитах на агента и на тенанта.

Эта стоимость — цена точного предпросмотра. Режим «пропустить вызов LLM» не дал бы вам никакого представления о том, как агент будет вести себя на самом деле.

### Чтение результатов Dry Run

В [Истории запусков](#run-history) запуски в режиме Dry Run помечены значком **Dry Run** в столбце статуса. Действия внутри каждого запуска выглядят идентично рабочим действиям — то же имя инструмента, те же аргументы, то же обоснование и уверенность — за исключением того, что ни одно из них не было выполнено.

[Страница аналитики](#analytics-page) показывает разбивку запусков «dry-run vs live» по месяцам, чтобы вы могли видеть, какая часть расходов на токены ушла на наблюдение.

### Переключение из режима Dry Run

Отредактируйте агента и измените **Статус** на **Enabled**. Следующий триггер запустится в рабочем режиме.

Вы также можете переключиться в обратном направлении — с Enabled обратно на Dry Run — если агент начнёт делать то, что вам не нравится. Никаких штрафов за это нет.

### Повторы всегда выполняются в режиме Dry Run

Функция [Тестовые запуски (повторы)](#test-runs-replays) запускает агента на исторических комментариях **всегда в режиме dry-run**, независимо от сохранённого статуса агента. Повторы не могут выполнять реальные действия над прошлыми комментариями. Это сделано намеренно — повтор — это инструмент предпросмотра, а не инструмент модерации.
