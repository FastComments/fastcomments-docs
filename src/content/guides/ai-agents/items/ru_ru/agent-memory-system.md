Память агента — это ограниченная тенантом, **общая** коллекция ключ-значение, из которой каждый агент в вашем тенанте может читать и в которую может писать. Она существует для того, чтобы агенты могли переносить контекст между запусками.

### Зачем нужна память

Контекст LLM существует только в рамках одного запуска. Без памяти агент, выдавший предупреждение пользователю, никак не узнает об этом предупреждении при следующей встрече с тем же пользователем. Политика эскалации платформы — «сначала предупреждение, потом бан» — зависит от способности агента найти предыдущее предупреждение. Именно память делает это возможным.

### Два вида памяти

- **WARNING** — записывается автоматически как часть процесса [`warn_user`](#tool-warn-user). Агент не создаёт записи `WARNING` вручную; они являются побочным эффектом выдачи предупреждения пользователю.
- **NOTE** — записывается через [`save_memory`](#tools-overview). Общий контекст, который агент хочет сообщить будущим агентам.

Политика эскалации при решении, оправдан ли бан, ищет именно записи `WARNING`.

### Ограничено тенантом, общее для агентов

Все агенты в вашем тенанте используют **один пул памяти**. Заметка, сохранённая агентом A, видна в вызовах `search_memory` агента B. Это сделано намеренно — заметки агента триажа должны влиять на решения агента-модератора.

`tenantId` устанавливается исполнителем на основе тенанта самого агента — никогда из аргументов LLM, — поэтому утечки памяти между тенантами невозможны по построению.

### Что содержит запись памяти

Каждая запись памяти содержит:

- **Какой агент её создал**, и когда.
- **О ком она** — пользователь, которого касается эта память. Агент не может подделать это поле; платформа заполняет его автоматически на основе того, что вызвало агента.
- **Скрытый сигнал об альтернативных аккаунтах** — платформа также (приватно) сохраняет IP-отпечаток исходного комментария, чтобы будущие поиски по памяти могли показать заметки о других аккаунтах, публикующих с того же IP. Отпечаток никогда не показывается агенту или LLM.
- **Сама заметка** — до 2000 символов свободного текста.
- **Теги** для поиска — до 10 коротких тегов.
- **Тип** — либо предупреждение, либо общая заметка.
- **Необязательная ссылка на комментарий** — если память привязана к конкретному комментарию.

### Поведение поиска

[`search_memory`](#tools-overview) возвращает до 25 записей, отсортированных от новых к старым, автоматически ограниченных областью (пользователь триггера) ИЛИ (другие аккаунты с IP триггера). Результаты также ограничены по объёму — 8000 символов суммарно по всему возвращаемому содержимому; при достижении лимита более старые записи отбрасываются.

Агент не передаёт `userId` или `targetIpHash`. Оба значения устанавливаются исполнителем.

### Хранение

У памяти **нет TTL**. Записи сохраняются, пока не будут явно удалены. Записи WARNING о пользователе намеренно никогда не удаляются автоматически — история эскалации должна быть доступна для поиска неограниченно долго, иначе проверка «поиск перед баном» теряет смысл.

Три способа удаления памяти:

- Модератор удаляет исходный комментарий — вся память, привязанная к этому комментарию, удаляется каскадно.
- Пользователь удаляется — все записи памяти о нём удаляются в той же транзакции.
- Ваш тенант удаляется.

На сегодня нет админ-интерфейса для удаления отдельных записей памяти.

### Память в режиме dry-run

Агенты в режиме dry-run **не** записывают память. Это сделано намеренно: гипотетические решения агента в dry-run не должны засорять общий пул памяти. Чтение через `search_memory` в dry-run работает как обычно — агент видит реальные записи от «живых» агентов — просто он не может их дополнять.

### Память в реплеях

Как и в dry-run: агенты в реплеях не записывают память. Реплеи предназначены только для предпросмотра. См. [Test Runs (Replays)](#test-runs-replays).

### Сводка ограничений

| Ограничение | Значение |
|---|---|
| Максимальная длина содержимого памяти | 2000 символов |
| Максимальная длина тега памяти | 64 символа |
| Максимальное количество тегов памяти | 10 |
| Максимальная длина запроса к памяти | 200 символов |
| Лимит результатов поиска по памяти | 25 записей |
| Общий лимит содержимого результатов поиска | 8000 символов |
