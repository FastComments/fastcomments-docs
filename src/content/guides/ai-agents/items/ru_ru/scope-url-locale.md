По умолчанию агент работает на всём вашем тенанте — на каждой странице, в каждой локали. Разделы **Scope** и **Locales** в форме редактирования позволяют это ограничить.

### Ограничение определёнными страницами

Поле **Restrict to specific pages** принимает один URL-шаблон на строку в синтаксисе url-pattern glob. Агент запускается только для комментариев, URL страницы которых совпадает хотя бы с одним из шаблонов. Примеры:

- `/news/*` — любая страница в разделе `/news`.
- `/forums/*` — любая страница в разделе `/forums`.
- `/blog/2026/*` — любая страница в разделе `/blog/2026`.
- (несколько строк вместе) — агент запускается, если совпадает **любой** из шаблонов.

Максимум: 50 шаблонов на агента. Шаблоны должны быть корректными url-pattern glob — форма отклоняет некорректные с конкретной ошибкой.

Если поле **пустое**, агент работает на каждой странице тенанта.

Если поле **не пустое**, агент работает по принципу fail closed: любой триггер, у комментария которого нет `urlId` (например, события уровня тенанта без контекста страницы), пропускается. Это сделано намеренно — «ограничено /news/*» не должно молча превращаться в «всё подряд».

### Ограничение определёнными локалями

Двухсписочный селектор **Restrict to specific locales** принимает идентификаторы локалей FastComments (`en_us`, `zh_cn`, `de_de` и т.д.). Агент запускается только для комментариев, определённая локаль которых входит в выбранный список.

Определённая локаль берётся из поля `locale` комментария, которое устанавливается виджетом комментариев в момент публикации на основе локали страницы.

Если **локали не выбраны**, агент работает во всех локалях.

Если выбрана **одна или несколько локалей**, агент работает по принципу fail closed: триггеры без комментария, а также триггеры для комментариев без поля `locale`, пропускаются.

### Комбинированное ограничение

Фильтры по URL и локали объединяются логическим И. Триггер запускает агента, только если **оба** фильтра это разрешают.

Полезные комбинации:
- URL-шаблон `/news/*` + локаль `en_us` — только англоязычный раздел новостей.
- Без URL-фильтра + несколько локалей — на весь тенант, но только для тех языков, на которые написан промпт этого агента.

### Зачем ограничивать агента

- **Стоимость.** Ограничение сокращает объём триггеров, которые должен обработать агент, а значит и расходы на токены.
- **Корректность.** Промпт для суммаризации, настроенный на технические статьи, может давать плохой результат на страницах товаров. Ограничение — более точный инструмент, чем просьба в промпте «пропускать нетехнические страницы» на английском.
- **Поведение по локали.** Приветствующий агент, который пишет только на немецком, должен запускаться только для комментариев с немецкой локалью. Совместите ограничение по локали `de_de` с немецкоязычным тоном в [начальном промпте](#personality-prompt).

### Чего ограничение *не* делает

- Оно не меняет **количество слотов агентов** (см. [Plans and Eligibility](#plans-and-eligibility)) — ограниченный агент по-прежнему занимает один слот.
- Оно не меняет [лимиты бюджета](#budgets-overview) — дневные и месячные лимиты на агента применяются ко всем подходящим триггерам.
- Оно не распространяется задним числом на прошлые запуски — история запусков показывает всё, что делал агент, даже если вы впоследствии ужесточили ограничения.
