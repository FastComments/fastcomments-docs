Натискання **View** у рядку [Run History](#run-history) відкриває сторінку деталей окремого запуску. Саме тут ви читаєте міркування агента та оцінюєте його рішення.

### Вгорі: підсумок запуску

- **Agent** - який агент виконував запуск.
- **When** - час запуску.
- **Status** - Started / Success / Error, а також бейдж **Dry Run**, якщо застосовується.
- **Cost** - вартість запуску у валюті вашого тенанта.
- **Cost per action** - вартість, поділена на кількість дій, що не очікують виконання; корисно для виявлення незвично дорогих запусків.

### Виконані дії

Список, у порядку виконання, кожного виклику інструменту, який зробив запуск. Кожен запис показує:

- **Action label** - "Wrote a comment", "Marked a comment as spam", "Banned a user" тощо. Назва відповідає enum типу дії.
- **Reference ID** - ідентифікатор зачепленого коментаря, користувача або бейджа, показаний моноширинним текстом (не гіперпосиланням).
- **Agent reasoning** - обґрунтування, яке агент надав разом із викликом.
- **Confidence** - самооцінка впевненості агента, показана у відсотках.
- Бейдж **Pending approval** - якщо дія поставлена в чергу в [папці схвалень](#approval-workflow) замість виконання.

Якщо запуск не виконав жодної дії, у розділі зазначено: "No actions were taken during this run."

### Транскрипт LLM

Під діями - повний транскрипт розмови агента з LLM:

- **System** - системний промпт (суфікс платформи + ваш початковий промпт + правила спільноти).
- **User** - контекстне повідомлення, що описує тригер.
- **Assistant** - відповіді моделі, включно з викликами інструментів.
- **Tool** - результат інструменту, переданий назад моделі (наприклад, що повернув `search_memory`).

Довгі повідомлення можна згортати; натисніть **Expand** / **Collapse**, щоб переглянути.

### Читання транскриптів

Транскрипт - найважливіша сторінка для налаштування. Коли агент приймає рішення, з яким ви не погоджуєтесь, прочитайте його, щоб побачити:

- Що модель **бачила** (контекстне повідомлення User).
- Що модель **вирішила** (виклики інструментів Assistant).
- Що модель **врахувала** (будь-які результати інструментів - наприклад, чи справді агент викликав `search_memory` і чи знайшов щось перед блокуванням).

Якщо модель послідовно припускається однакових помилок, відредагуйте [початковий промпт](#personality-prompt) - або скористайтеся [Refining Prompts](#refining-prompts) зі схвалення, яке було відхилено.

### Посилання на дії

Ідентифікатори показані моноширинним текстом (не гіперпосиланнями):

- Коментарі: ID коментаря.
- Користувачі: ID користувача.
- Бейджі: ID бейджа.

Ви можете скопіювати ID, щоб знайти зачеплений запис на відповідній сторінці модерації/адміністрування.

### Чого немає в dry-run

Запуски в режимі dry-run показують **ті самі** дії, обґрунтування та оцінки впевненості. Єдина відмінність - бейдж **Dry Run** у рядку статусу. Ідентифікатори коментарів / користувачів / бейджів все одно показані - агент просто не вплинув на них.

### Помилки

Для запусків у стані `Error` сторінка деталей показує основне повідомлення про помилку. Типові помилки:

- **No LLM API key configured** - неправильна конфігурація тенанта або платформи.
- **LLM call timeout** - провайдер LLM працював повільно або був недоступний.
- **Tool dispatch failure** - агент обрав інструмент із некоректними аргументами (наприклад, ID коментаря, який більше не існує).
- **Budget exhausted mid-run** - ліміт агента було вичерпано під час виконання запуску. Запуск було зупинено.

Помилки не відкочовують часткові дії - усі виклики інструментів, завершені до помилки, залишаються.
