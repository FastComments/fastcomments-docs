**승인(approval)**은 플랫폼이 실행하기 전에 사람이 승인하거나 거부해야 하는 대기 중인 도구 호출입니다.

### 승인 구성하기

에이전트 편집 폼의 **Approvals** 섹션에는 에이전트가 호출할 수 있는 모든 도구(허용 목록)가 나열되며, 사람의 검토가 필요한 도구를 체크할 수 있습니다. 체크하지 않은 도구는 즉시 실행됩니다. 체크된 도구는 대기열에 들어갑니다.

허용되지 않은 도구는 대기열에 들어가는 것이 아니라 *완전히 거부*됩니다. 승인은 다른 방식으로 허용된 도구에만 적용됩니다.

### 게이트가 적용된 작업이 실행될 때 어떤 일이 발생하는가

1. 에이전트가 인수, 근거, 신뢰도와 함께 도구 호출(예: `ban_user`)을 선택합니다.
2. 실행하는 대신, 플랫폼은 도구 이름, 인수, 근거, 신뢰도, 그리고 해당 호출을 유발한 트리거를 설명하는 컨텍스트 스냅샷과 함께 `PENDING` 상태의 승인을 대기열에 추가합니다.
3. 검토자에게 알림이 전송됩니다([승인 알림](#approval-notifications) 참조).
4. 에이전트의 실행이 완료되고 기록됩니다. 해당 작업은 [Run Detail View](#run-detail-view)에서 **Pending approval**로 표시됩니다.

### 승인 검토하기

[my-account/ai-agent-approvals](https://fastcomments.com/auth/my-account/ai-agent-approvals)의 승인 수신함에는 대기 중, 승인됨, 거부됨, 실행 실패 상태의 승인이 나열됩니다. 각 항목에는 다음이 표시됩니다:

- **도구 이름 및 인수** - 에이전트가 수행하려는 작업 그 자체.
- **에이전트 추론** - 에이전트가 제공한 근거.
- **신뢰도** - 에이전트가 스스로 평가한 신뢰도, 0.0에서 1.0 사이.
- **컨텍스트 스냅샷** - 작업이 대상으로 하는 댓글, 페이지, 사용자.

**Approve**와 **Reject** 두 개의 버튼이 있습니다. Approve는 실제로 도구를 실행하고, Reject는 폐기합니다.

### 승인 상태

승인은 다음 상태를 거칩니다:

| 상태 | 의미 |
|---|---|
| `PENDING` | 사람의 결정을 기다리는 중. |
| `APPROVED` | 사람이 승인했으며 작업이 실행됨. |
| `REJECTED` | 사람이 거부함. 작업은 실행되지 않음. |
| `EXECUTION_FAILED` | 사람이 승인했지만 작업이 실패함(예: 대상 댓글이 이미 삭제된 경우). |
| `EXECUTING` | 일시적 상태: 사람이 Approve를 클릭했으며 작업이 실행 중. 실제 부작용이 있는 도구가 두 번 실행되지 않도록 동시 승인 클릭을 직렬화하는 데 사용됨. |

`EXECUTING` 상태는 두 명의 검토자가 동시에 Approve를 클릭할 때 중요합니다. 한쪽이 이기고 다른 쪽은 승인이 이미 진행되었음을 보게 됩니다.

### 정리되는 항목

대기 중인 승인은 결정이 내려질 때까지 대기 상태로 유지됩니다. 생성 후 **90일**이 지나면 자동 만료됩니다. 다른 상태의 승인도 저장소 위생을 위해 90일 후에 삭제됩니다.

승인의 "decided by" / "decided at" / "executed at" / "execution result" 필드는 승인이 상태를 거치면서 채워지며, 수신함 상세 보기에서 모두 볼 수 있습니다.

### 웹훅 통합

승인이 진행됨에 따라 두 가지 웹훅 이벤트가 발생합니다:

- **`approval.requested`** - PENDING 상태로 삽입될 때.
- **`approval.decided`** - APPROVED, REJECTED 또는 EXECUTION_FAILED로 전환될 때.

두 이벤트 모두 다른 모든 웹훅과 마찬가지로 서명됩니다. [Webhook Events](#webhook-events) 및 [Webhook Payloads](#webhook-payloads)를 참조하세요.

### 강화: 알려진 도구 게이트

승인 기능은 인식된 에이전트 도구가 아닌 도구 이름은 대기열에 추가하는 것을 거부합니다. 이는 심층 방어(defense-in-depth) 검사입니다. 향후 코드 경로가 LLM에서 파생된 도구 이름을 승인 흐름에 전달하더라도, 해당 문자열은 대기 중인 승인으로 등록될 수 없습니다. 알려진 도구 이름 집합은 [Tools Reference](#tools-overview)에 나열된 것과 동일한 집합입니다.

### 일반적인 게이트 패턴

- **새로 도입된 검토 에이전트** - `ban_user`, `mark_comment_spam`, `mark_comment_approved`, `send_email`에 게이트를 적용합니다. 몇 주간 수신함을 관찰한 후, 오류가 적은 도구는 게이트를 제거합니다.
- **장기 운영 검토 에이전트** - `ban_user`와 되돌릴 수 없는 작업(`deleteAllUsersComments`, `banIP`)은 영구적으로 게이트를 유지합니다.
- **EU 지역** - 체크 여부와 관계없이 제17조에 따라 `ban_user`는 잠깁니다. [EU DSA Article 17 Compliance](#eu-dsa-compliance)를 참조하세요.

### 승인이 하지 **않는** 것

- 에이전트의 다른 도구 호출을 지연시키지 않습니다. 에이전트의 실행은 여러 도구를 호출할 수 있으며, 게이트가 적용된 도구만 대기열에 들어가고 나머지는 정상적으로 실행됩니다.
- 사람이 거부하더라도 에이전트의 실행을 롤백하지 않습니다. 실행 중 게이트가 적용되지 않은 부분은 이미 완료되었습니다.
